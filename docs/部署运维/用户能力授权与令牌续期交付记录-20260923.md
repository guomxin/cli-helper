## 发布与恢复约束

上次认为缺失的配置实际存在于 `%LOCALAPPDATA%\AgentBridge\deploy\production\environment.json`。它描述部署主机、目录和已复核的 systemd 单元文件及摘要，属于本机运维配置，不是用户需要另行准备的业务数据文件。

本次新增三张授权/续期表及令牌的两个字段，使用 `reviewed-schema-transition` 显式声明完整结构前后摘要，其余数据库结构必须不变；没有冒用 `no-migration`。升级前已生成并验证恢复点：

`/home/guomao/agentbridge/backups/agentbridge-20260923T103330Z-dcdc8ab3.manifest.json`

迁移后旧版本不理解用户细粒度权限，禁止自动退回旧程序或恢复旧数据覆盖新的撤权记录。失败应保留证据并使用兼容新授权的修复版本。

发布入口现要求 PowerShell 7。Windows PowerShell 5 曾在升级成功后的中文验收脚本解析处失败；本次通过 PowerShell 7 的 `-ResumeAcceptance` 完成验收和推送，没有重复部署或重启。常规入口：

```powershell
pwsh -NoProfile -File scripts/Publish-AgentBridge.ps1 -EnvironmentProfile "$env:LOCALAPPDATA\AgentBridge\deploy\production\environment.json" -PlanOnly
```

日常操作：管理台“用户与令牌”中配置用户业务能力，在令牌行点击“续期”；原客户端凭证继续使用。新用户仍可通过兼容签发入口建立身份，然后在同页配置用户业务能力；未迁移账号明确保留旧 Scope 模式，不与已配置用户双重授权。
