# 维护治理与扩容边界

## 代码边界

业务写入名称、字段 Schema、函数绑定和权限表集中在 `bscli/core/write_catalog.py`；中央服务不再通过自身全局符号查找业务函数。新增业务先注册绑定，再补模拟测试。

`controlled_write_executor.py` 承担可信字段准备与单次授权提交；它与中央服务共享同一组账本、锁和事务，不创建新的数据库提交边界。`login_recovery.py` 只恢复账本中原用户、原任务、原系统的读取与精确参数。OpenClaw 的 `read-continuation.js` 负责读取描述及展示，原任务事实仍由中央账本决定。计划执行继续由已有 `task_plan_runtime.py` 管理；通知领取、投递和确认仍集中在中央服务，后续可在同一回归保护下继续拆分，不以拆小文件为完成标准。

保护契约：取消不得穿过授权消费边界，结果未知不得重放，普通读取各有任务，登录恢复保留原任务，重复通知不得重复业务执行。M4 的真实 Node—Python—SQLite 测试与受控写边界测试共同保护这些行为。

## 当前事实和发布检查

执行 `python scripts/current_facts.py --write` 更新当前状态的生成区，`--check` 检测漂移。版本来自插件 package.json，数量来自实际构造的注册表与 MCP；不推断已经部署或已经通过真实业务验收。历史验收数字仍属于各自日期。

正式发布顺序：本地固定候选全量验证 → 将相同提交推送到 `candidate/<完整提交号>` → GitHub `candidate-validation` 成功 → 同一已验证 wheel 部署 → 在线验收 → 推送 main。CI 不接收生产凭据，也不负责部署。重复运行只接受该提交、候选分支、push 事件、指定工作流的最新执行；失败、取消、跳过或无法读取结果都阻断部署。`-SkipValidation` 仍必须匹配本地完整回执，不能跳过候选 CI。

仓库管理员还须为 main 启用必需状态检查 `candidate-validation`，要求分支最新、禁止强推与删除、对管理员同样执行；不要设置绕过主体。先让候选 CI 实际运行并确认发布顺序，再启用规则。CI 文件和本地门禁不能替代远端分支保护；规则生效要单独读回核验。2026-09-21 开工核验：main 未保护，规则集为空；此为待闭环事项。配置含义参见 [GitHub 必需检查说明](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches)；本地部署门禁仅接受 success，比平台允许的 skipped/neutral 更严格。

## 环境配置与公开内容

`deploy/systemd` 是通用示例，使用回环监听及 `.example.test` 下游；默认 TLS，不继承照明明文例外。实际三个运行/备份单元放在仓库外，由 `agentbridge.environment.v1` 配置文件列出 host、root、各单元绝对路径和 SHA256。

发布必须显式传入 `-EnvironmentProfile <仓库外配置文件>`，也可由受控运行环境设置 `AGENTBRIDGE_ENVIRONMENT_PROFILE`。PlanOnly 展示配置路径及单元摘要；目标、文件位置或摘要不符立即拒绝，读取后固定本次使用的字节。配置含真实端点，不能提交仓库；私钥、会话密文、业务结果和完整运行日志也不得放入公开 CI 产物。

原环境配置迁移须先原样复制并核对哈希，再将模板脱敏。服务器仍通过原发布事务安装、核验、切换和回退。恢复点包含服务器配置；发布电脑上的受控配置应按组织制度另行备份。历史文档和运维辅助脚本尚含真实布局，不宣称整个 Git 历史已经脱敏，不重写历史。每次公开发布仍需人工复核业务内容；高置信凭据扫描通过不能替代此项。

## 传输例外清单

| 链路 | 数据及限制 | 已有控制 | 尚缺证据 | 责任角色与复核 | 退出条件 |
| --- | --- | --- | --- | --- | --- |
| 既有照明系统 HTTP | 中央会话 Cookie/JWT 及已开放业务请求；仅既有试点 | 显式不安全传输开关，适配器权限及受控写规则 | 未证明链路有 VPN/专线等额外加密，不视为传输已保护 | 下游系统与部署维护者；2026-10-01 前及扩大范围前复核 | 提供 HTTPS 与可信证书，完成登录、只读、授权链路回归后移除 HTTP 开关 |
| 既有日志数据库 TLS 关闭例外 | 只限代码中精确旧源；账号、查询和报表仍按既有授权 | 固定旧源匹配、只读事务、关系及函数白名单 | 未证明网络补偿措施，未完成数据库证书改造 | 数据库与部署维护者；2026-10-01 前及接入高敏数据前复核 | 服务端 TLS、主机名验证与可信 CA，连接预检和只读回归通过后删除例外 |

责任角色是工作分工，尚未确认具体责任人。上述两项保留为未关闭例外；不能将登记本身算作安全验收通过。证书错误不能自动降级成明文。扩大用户、数据敏感度或外部暴露前，须落实保护方案并复核，不自动沿用试点结论。

## 资源预算及容量限制

| 层级 | 预算 | 超限行为 |
| --- | --- | --- |
| Auth/Admin/Workspace 每个 HTTP 服务 | 最多 64 个处理连接、每来源 IP 16 个、监听队列 64 | 在线程创建前拒绝新连接，不信任转发头改变来源 |
| TLS 握手 | 10 秒 | 关闭连接并归还额度 |
| 请求头/请求体读取、普通响应写入 | socket 空闲 30 秒；连接绝对寿命 360 秒 | 超时断开；慢速持续发送不能无限延长寿命 |
| 请求体 | Admin 64 KiB，Workspace 普通请求 128 KiB，聊天 18 MiB；Auth 沿用既有限额 | 沿用既有长度检查，认证/CSRF/Origin 边界不变 |
| Workspace SSE | 每已认证 user_subject 最多 6 路，写入超时 30 秒，连接寿命 360 秒 | 第 7 路返回 429；退出和断流释放额度；事件/时间线仍按既有 25 秒轮换重连 |
| MCP Uvicorn | 并发 128、队列 64、keep-alive 5 秒 | 超载拒绝；不代表已完成 MCP 慢请求头和每身份独立配额治理 |

连接额度不等于每用户业务执行预算。来源 IP 限制对共用 NAT 的用户合并计数，应在负载验收后调整。到达全局额度时健康检查也可能被拒绝；不能宣称抵御了分布式耗尽。MCP 握手/请求头独立预算、端到端排队策略、实际容量基准仍应在扩大试点前补齐。新预算的隔离测试与生产健康验收分别记录。
