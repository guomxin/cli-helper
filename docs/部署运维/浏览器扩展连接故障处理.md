# 浏览器扩展连接故障处理

## 适用范围

这里指 Codex 当前使用的 Chrome 控制扩展，不是 AgentBridge 已退役的旧浏览器桥。
用于恢复开发与 Workspace 页面验收，不改变业务身份、权限和中央 OA 登录会话。

## 2026年9月7日实测结论

| 检查 | 结果 |
| --- | --- |
| 扩展发现 Chrome 和已打开标签页 | 成功 |
| 原 Workspace 标签页读取 | 重复返回 `Debugger unattached` |
| 重置当前 CUA 控制会话 | 未恢复原页 |
| 扩展安装状态 | 已安装、已启用，无禁用原因 |
| Native Messaging 清单与真实用户注册项 | 正确 |
| 原管理控制台页面读取 | 成功 |
| 使用完整标签页身份重新领取原 Workspace | 仍失败 |
| 同一 Chrome 配置新建 Workspace 页 | 成功，复用 `xinguomao` 登录 |
| 新页导航、历史消息和应用卡读取 | 成功；未发起业务请求 |
| 原页单独刷新 | 控制接口仍报错，原页保留 |

结论：已解除页面测试阻塞，但没有修复原标签页的调试器状态，也不能宣称扩展内部缺陷已根治。
证据将问题缩小到原标签页的控制连接，不支持“扩展未安装”“全部站点无法访问”或“OA 登录失效”的判断。
触发该状态的底层原因尚不明确；不据此猜测是网络、HTTP、证书或用户权限问题。

## 固定恢复顺序

1. 获取当前浏览器与标签页清单，区分普通窗口的第一用户和无痕窗口的第二用户。
2. 先直接控制用户已打开的指定 Workspace；一次明确的连接失败后，不反复操作同一失效对象。
3. 再尝试在原浏览器、同一身份上下文新开相同 Workspace 地址的标签页，验证身份和导航。
   若包含建页、导航及初始读取的单次调用超时，将三步拆开调用；先保存新页句柄，再导航，再读取状态，避免超时后重复建页。2026年9月8日以此方式恢复第一用户页面，并实际发起只读组合验收。
4. 新页仍失败，或者工具无法在原无痕窗口开页时，立即请用户协助在相应窗口新开页或恢复连接。不要长时间盲目排查，也不要用第一用户普通窗口冒充第二用户。
5. 用户恢复后继续原定验收，核对请求、应用卡、终态和后台证据；不能因一次连接失败而把任务停在不完整状态。
   如果现有浏览器对象的标签页列表仍未出现用户新页，重新获取全局浏览器状态，再按新标签页编号连接；不要据旧列表断定用户没有开页。9月8日中午按此步骤找到新的无痕页并确认 `lishiyu` 身份。
6. 页面初始加载未完成或可访问性树被截断时，不把空列表或缺少尾部消息判定为数据丢失。
7. 保留需要继续验收的恢复页，不擅自关闭原用户页面、清除站点数据、退出登录或复制 Cookie。安装与 Native Messaging 检查仅在明确需要时进行。

上述操作只恢复浏览器控制。真正业务验收仍需分别验证请求、卡片、执行结果和跨端同步。
不要将恢复页面成功当作尚未部署功能的验收通过。

## 安装检查的注意事项

### 9月8日普通与无痕窗口补验

- 普通窗口新建 Workspace 页后，可通过扩展的可访问性接口读取身份、输入请求、切换任务和打开应用卡；实际完成只读查询与测试卡失效后的页面核对。
- 第二用户无痕旧页仍报 `Debugger unattached`。用户在原无痕窗口新开标签页后，扩展成功读取 `lishiyu` 身份，发起 OA 会话查询并看到正确答复。
- 本轮工具的新建标签页接口没有指定无痕窗口的参数。不能用普通窗口的新页代替第二用户，也不能转移 Cookie；遇到这种限制，让用户只在原无痕窗口新开页即可，不要求重新登录 OA。
- 普通新页使用扩展内的 Playwright 读取时曾再次出现调试器未连接；后续新页采用 `getAXState`、`setValue`、`click` 完成验收。这里只记录观察到的差异，不认定 Playwright 调用就是缺陷根因。
- 长聊天的可访问性树可能只返回前 500 个子项。读取不到尾部消息不等于页面没有消息，应切换任务详情并结合后台记录核对，不能据此判断同步失败。
- 在连接正常的新页中，扩展自带的 DOM 快照能补足长聊天可访问性树截断的尾部消息；它仍通过 Chrome 扩展操作当前用户页面，不是启动独立 Playwright 浏览器。

以上证明“同窗口新页恢复”对本轮普通和无痕页面均有效，不等于原页连接故障已经根治。

优先使用当前已安装 Codex 浏览器插件自带的只读诊断脚本：

- `check-extension-installed.js --browser chrome --json`
- `check-native-host-manifest.js --browser chrome --json`

脚本路径包含插件版本，须先定位当前路径，不能把本次版本硬编码进长期自动修复程序。
Windows 沙箱里的 HKCU 不一定是交互用户的 HKCU。本次沙箱检查误报注册项不存在，
正式获准的真实用户上下文只读复核显示清单和注册项完全匹配，因此没有修改注册表。

不要直接编辑 Chrome 配置、删除扩展目录、开放调试端口、放宽站点权限、清除 Cookie，
也不要启动另一套 OA 登录把中央保活会话踢下线。
