# 独立备份节点操作手册

2026-09-20，用户提供 10.10.50.209 作为备份目标后，已配置该机主动拉取 10.10.50.213 的 M2/v2 恢复点。它是独立机器副本；是否处于不同机房、供电和存储故障范围尚未核实，不直接称为异地容灾。

## 运行方式

| 项目 | 当前设置 |
| --- | --- |
| 源 | 213 的 `/home/guomao/agentbridge/backups`，仅完整 v2 清单与对应 zip |
| 目标 | 209 的 `/srv/agentbridge-backups/213/agentbridge-GENERATION/` |
| 调度 | 209 的 `agentbridge-backup-pull.timer`，每小时 00、30 分拉取；开机补运行 |
| 保留 | 209 独立保留 90 天，至少 7 代；源端删除不会同步删除目标历史 |
| 过期检查 | 最新源备份超过 36 小时或时钟明显超前，任务失败，不更新成功报告 |
| 校验 | 清单、压缩包摘要与大小；已有代次摘要变化时拒绝覆盖 |
| 失败可见性 | systemd 失败状态及 journal；未配置邮件、微信或其他主动通知 |
| 成功记录 | `/srv/agentbridge-backups/213/last-success.json` |

每 30 分钟是复制检查频率，不是生成新备份的频率；213 仍每日生成备份，并在发布时额外生成。恢复点新鲜度仍以源恢复点时间为准。

209 现有 Python 2.7.5、systemd 219，无系统升级。复制脚本兼容该环境，仅处理本地文件与 SSH；不在 209 启动应用服务或连接业务数据库。新增运维组件不改变已安装中央应用版本，不触发中央服务或 OpenClaw 重启。

## 凭据与边界

- 初次登录使用用户提供的凭据，未写入仓库、脚本或定时任务。管理使用本机 SSH 目录内的 209 专用密钥；现有 SSH 配置和其他主机密钥保留。
- 拉取私钥仅保存在 209 的 `/etc/agentbridge-backup/pull_ed25519`，目录 0700、文件 0600；213 只安装对应受限公钥。
- 213 上该公钥限定来源地址 209，使用 `restrict` 和固定命令，只允许 `list`、`get <有效代次> manifest|archive`；禁止 shell、SFTP、转发和任意路径读取。固定命令通过 root 账号进入后立即降为 agentbridge 身份。实现依据：[OpenSSH authorized_keys](https://man.openbsd.org/sshd.8#AUTHORIZED_KEYS_FILE_FORMAT)。
- 固定导出脚本为 root 所有的 `/usr/local/libexec/agentbridge-backup-export.py`，读取备份目录，不读取应用解密密钥。209 固定已有的 213 主机公钥，不采用关闭主机验证的方式连接。
- 应用的 session.key 没有随包复制到 209。独立密钥保管仍需指定另外的受控位置和保管人；备份拉取密钥不等于应用解密密钥。
- 历史副本由 209 管理，213 没有因此获得访问 209 的凭据。本方案不是 WORM/不可变存储；209 的 root 仍可删除本机副本。

## 操作与故障检查

以下命令在 209 执行：

```sh
systemctl list-timers agentbridge-backup-pull.timer --no-pager
systemctl show agentbridge-backup-pull.service -p Result -p ExecMainStatus
journalctl -u agentbridge-backup-pull.service -n 50 --no-pager
cat /srv/agentbridge-backups/213/last-success.json
systemctl start agentbridge-backup-pull.service
```

服务失败时先查看日志和最后成功时间。源备份过期应先核查 213 的备份服务；摘要变化不得删除旧副本来让任务通过。中断只留下未发布的 `.incoming-*` 暂存目录，不构成成功代次。自动正常失败会清理本次暂存；进程被强杀后可由管理员核对再清理。脚本不通过源端的列表缺失来删除历史。

系统定时器保证同一服务不并行运行；手工也使用 `systemctl start`，不要另起多个复制进程。需要暂停时使用 `systemctl disable --now agentbridge-backup-pull.timer`，保留已有备份。撤销读取能力时仅移除 213 authorized_keys 中带 `agentbridge-pull-209` 的专用行，不修改其他 SSH 授权。

恢复时从 209 取回完整代次目录，使用[完整恢复基线操作手册](./完整恢复基线操作手册.md)在支持当前应用版本的隔离环境校验、恢复，并从独立保管处提供匹配的应用密钥；不能在 209 的 Python 2.7 上直接运行 M2 应用恢复模块。
