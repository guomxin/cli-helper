# 多数据库迁移与验收记录

日期：2026-09-14。代码已实现，线上发布与 Workspace 验收待完成。

## 使用与接入

管理控制台新增“数据库”入口。每个数据源独立保存连接、开放对象、能力包及查询预算；先保存草稿，再执行只读预检，最后启用。编辑草稿及失败预检不替换正在使用的配置。停用后目录、查询、文件下载均拒绝此源，其他源继续工作。保存、预检、启停采用版本校验并记录管理员及变更原因。

首期支持 PostgreSQL，新增源要求 `verify-full` TLS；服务使用 PostgreSQL 默认根证书位置或服务环境 `PGSSLROOTCERT`。已有泰华内网源保留原传输配置。通用包提供 schema、自由只读 SQL、CSV；泰华日志包追加目录、日志、正文和评论能力。开放对象填写完整的 `schema.table`，源库账号必须只读且无写入、临时表及高权限角色权限。

账号按“中央账号 × 数据源 × 能力”授权。Token 只承担身份认证，授权更改即时生效，无需重新签发或重启。保留原授权范围；CSV 导出独立授权，下载还校验原查询权限、所有者、源版本和授权版本。用户已明确批准给 guomao、lishiyu 增加泰华日志库导出与下载权限，待上线后执行。

智能体先用 `database_capabilities` 选择数据源，再以 `database_execute` 明确 `source_id`。两个时间窗口比较使用 `database.free.read`，不再创建专用比较计划。取消按历史结果 ID 读取原始分析结果；追踪 query_id 不提供读取入口。

CSV 由 `database.report.export` 根据查询定义重新查询，支持自由 SQL、日志明细与数值统计。`request_key` 防止重复执行，相同键不同定义拒绝，失败键不会自动重放。`database.report.download` 交付加密保存的短期文件；文件保留最多 24 小时，认证下载窗口最多 10 分钟。源或授权版本变化后旧文件失效，恢复授权不会复活旧文件。

## 迁移与退役

旧 `analytics/source.json` 和加密凭据只在目标源不存在时导入 `database/catalog.sqlite3`；旧 `database_grants` 仅向 `(账号,taihua_primary)` 补齐缺失记录。已迁移源和授权撤销记录优先，重复启动不会重置它们。历史源配置、凭据和历史结果保留，不删除源库数据。

`taihua:analytics:*` 不再可签发；对应 MCP 工具、中央能力、专用比较变换和计划目录入口已移除。旧 Token 仍可认证，其旧 scope 不产生数据库授权；旧直接能力调用及旧历史下载明确拒绝。普通泰华业务 API 不变。保留旧底层模块供历史数据格式和离线测试使用，不构成在线能力入口；后台不再清理旧分析历史。

发布前检查旧分析运行中计划和未过期文件均为 0。生产迁移前备份位于 `/home/guomao/agentbridge/data/migration-backups/database-20260914`。回滚必须同时评估旧能力会重新暴露的影响：先停用新数据库入口，保留现有 grants/catalog/reports 数据，使用固定部署入口回滚代码；禁止把旧授权备份直接覆盖现行授权。回滚后若需恢复旧分析入口，应独立确认授权边界。
