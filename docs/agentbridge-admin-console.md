# AgentBridge 管理控制台

> 适用范围：当前内网中心部署 `10.10.50.213`
>
> 管理入口：`https://10.10.50.213:8782`

## 1. 定位

管理控制台是 AgentBridge 的独立运行治理面，用于查看多用户、多系统的运行状态，并在异常或维护期间控制写能力。它不代替 OpenClaw，不直接操作 OA、泰华或语雀业务，也不展示登录凭据、Cookie、可信卡片 URL、业务字段值或 MCP Token 密钥。

普通用户使用的 Agent Workspace 是与 Telegram、微信同层的独立智能体客户端，
不复用管理端账户、页面或会话。其目标边界见
[多端智能体任务延续设计](./omnichannel-agent-task-continuity-design.md)。

管理端与 MCP、可信卡片共用一个 AgentBridge 进程和 SQLite 状态库，但使用独立的 HTTPS 监听端口、管理员账户、会话 Cookie、CSRF 校验和追加式管理审计。

## 2. 角色

| 角色 | 能力 |
| --- | --- |
| `admin` | 查看全部治理信息；签发和撤销 MCP Token；检查或使下游会话失效；暂停和恢复写能力；创建管理员或审计员账户 |
| `auditor` | 只读查看总览、身份、会话、能力、操作、可信交互、多端任务、运行信息和管理审计 |

管理账户与智能体用户身份分离。管理员登录管理台不会获得任何 OA、泰华或语雀业务身份，也不能通过管理台代替用户提交业务流程。

## 3. 页面

- **运行总览**：接入用户、活动会话、活动任务、端点、待投递、写暂停、最近 24 小时异常和隔离完整性。
- **用户与令牌**：按 `userSubject` 汇总各系统下游主体、系统会话和 MCP Token；权限按系统分组显示，令牌密钥只在签发时显示一次。
- **系统会话**：分别显示每个系统的预期主体和已验证主体，并区分登录状态、用户活动、保活资格和最近保活；可实时检查、使会话失效，或在清除该系统登录态后重新绑定主体。
- **能力与策略**：查看能力目录，按全局、系统、用户或具体能力版本暂停和恢复写入；读取能力不受影响。
- **操作记录**：查看能力执行状态与错误码，不展示调用参数和结果正文。
- **可信交互**：查看认证卡、字段卡和授权卡的状态与有效期，不展示卡片 URL、字段值和执行计划。
- **多端任务**：按任务、端点、接续、投递和隔离五个视图检查 Task Hub。网页端显示为拉取投递，Telegram、微信等消息端显示为直推投递。
- **系统运行**：查看 Release ID、启动时间、数据库、保活租约、已配置系统、协调调用耗时和管理账户。
- **管理审计**：查看追加式审计记录，包括管理员、来源 IP、动作、原因、结果和前后状态。

列表页支持本地搜索和状态筛选。筛选只作用于当前已加载的治理记录，不会触发下游系统调用。

### 3.1 多端任务的安全投影

管理 API `v2` 的 `/api/coordination` 只返回任务治理所需的元数据：

- 任务 ID、用户、可读标题、状态、发起端类型和当前关联的操作/交互 ID；
- 端点 ID、客户端类型、拉取/直推模式、能力标签、状态和最近活动时间；
- 接续状态、执行模式、候选数量和有效期；
- 投递事件类型、状态、尝试次数、重试时间和确认时间；
- Task Hub 的跨用户隔离检查结果。

接口不返回聊天正文、任务摘要、业务字段、卡片 URL、外部聊天用户标识、会话路由、端点密钥、完整事件载荷或 MCP Token ID。多端任务页用于定位“任务卡在哪一步”和“消息是否送达”，不用于读取业务内容。

## 4. 首次初始化

部署并启动 AgentBridge 后，在服务器的受信终端创建首个管理员。密码只从标准输入读取，不出现在命令参数和程序输出中：

```bash
sudo -u agentbridge /home/guomao/agentbridge/venv/bin/python -P \
  -m bscli.cli.main --home /home/guomao/agentbridge/data \
  admin account bootstrap --username admin --password-stdin
```

只有管理账户表为空时才能执行 bootstrap。初始管理员第一次登录后必须立即修改密码。密码至少 12 位，并满足大写、小写、数字、符号中的三类。

后续账户由现有 `admin` 在“系统运行”页面创建。系统生成一次性初始密码，关闭弹窗后不能再次查看。

## 5. 登录安全

- 非回环地址必须使用 HTTPS；当前部署复用内部 CA 签发的 IP-SAN 证书。
- 会话 Cookie 为 `HttpOnly + Secure + SameSite=Strict`，CSRF Token 与会话绑定。
- 管理会话默认最长 8 小时、空闲 30 分钟；退出或失效后必须重新登录。
- 登录失败有来源 IP 维度的速率限制。
- 页面启用 CSP、HSTS、禁止被 iframe 嵌入和 MIME 嗅探。
- 管理审计表禁止更新和删除；控制动作必须填写原因。

## 6. 写暂停语义

暂停策略只作用于非只读能力，匹配优先级为：具体能力、用户、系统、全局。策略会在两个位置检查：

1. 准备字段卡或授权卡之前，阻止创建新的写交互；
2. 最终提交边界，再次阻止已经授权但尚未提交的操作。

命中策略时能力返回 `WRITE_PAUSED`，不会调用下游系统。恢复策略不会重放或自动重试之前被阻止的操作，用户需要重新发起。

## 7. MCP Token 管理

管理台签发 Token 时要求填写用户标识、权限范围、有效期和审计原因。首次开通某个系统时，还必须填写该系统的预期下游主体；已有绑定的系统会自动复用现有绑定。同一用户在 OA、泰华和语雀可以使用不同的账号或显示名。

Token 只绑定 `userSubject`、客户端标签和 scope，不再以一个全局姓名校验所有系统。旧 Token 中的 `expectedPrincipalRef` 仅作兼容字段；登录校验以 `(userSubject, systemId)` 会话上的系统级绑定为准。

管理员修改某个系统的主体绑定时，服务端会清除该系统会话密文并将状态设为已过期，要求用户重新登录；其他系统会话不受影响。

撤销 Token 立即阻止后续 MCP 调用，但不删除该用户已保存的下游会话。需要同时清除会话时，在“系统会话”页面单独执行失效操作。

## 8. 部署与健康检查

systemd 单元在现有 MCP `8790` 和可信卡片 `8780` 之外启动管理端 `8782`：

```text
--admin-host 10.10.50.213
--admin-port 8782
--admin-public-base-url https://10.10.50.213:8782
--admin-tls-cert /home/guomao/agentbridge/config/tls/server.crt
--admin-tls-key /home/guomao/agentbridge/config/tls/server.key
```

部署脚本把当前 Release ID 写入 `/home/guomao/agentbridge/config/release.env`，管理台“系统运行”页面据此显示实际发布版本。

无需登录的健康检查：

```bash
curl --cacert /path/to/root-ca.crt https://10.10.50.213:8782/healthz
```

预期返回 `status=ok`。健康检查只证明管理 HTTP 服务已监听，不代替登录、权限和治理动作验收。

## 9. 运维边界

当前一期刻意不提供以下功能：

- 在管理台中重启 systemd、执行 SSH 或修改服务器文件；
- 查看或导出凭据、Cookie、业务字段、授权内容和完整业务结果；
- 查看聊天正文、通道路由、外部聊天用户标识或完整 Task Hub 事件载荷；
- 以管理员身份代替业务用户调用下游系统；
- 自动清理、撤销或重放业务写操作；
- 声称单进程内逻辑隔离等同于独立 OS 或容器 Worker 的物理隔离。

涉及真实业务写入仍必须由对应智能体用户走字段卡、独立授权、提交和权威回读流程。
