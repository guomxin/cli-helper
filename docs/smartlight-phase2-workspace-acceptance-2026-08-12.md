## 四、问题与修复优先级

### P1 连续语句被误判为跨任务接续（已解决）

`TASK_CONTINUATION_HINT_PATTERN` 会把“查看巡检任务，并继续读取第 1 个任务每日进度”中的“任务...继续”识别为继续历史任务，导致模型列出旧任务而不是执行当前请求。

修复后，只有明确指向既有历史任务的表达才触发跨任务接续；当前句内已经包含业务对象和顺序动作时，继续在当前业务请求中执行。

### P1 候选项后的“导出”不能继续执行（已解决）

问题根因不只是缺少“导出”关键词，而是业务候选项序号和历史任务候选项序号没有可靠区分。仅扩大正则会继续产生误判。

修复后，协调器只在自己刚返回历史任务歧义列表时建立一个 10 分钟、会话内有效的候选标记；有该标记的序号选择才进入历史任务中心。普通业务列表的“第 2 项”保留给当前对话模型处理。真正的历史任务跟进仍允许受控报告导出，并继续绑定用户、会话和任务 ID。

### P2 模型回退过程泄露中间失败状态

主模型发生一次上游 `server_error` 后，OpenClaw 已回退到备用模型并成功返回，但 Workspace 曾显示 `The agent run failed before producing a reply.`。建议只在所有回退均失败后持久化终态失败；回退中的候选错误可进入诊断日志。

### P2 登录状态字段语义不清

AgentBridge 用户、Workspace 账号、目标系统账号和下游主体是四个概念。建议登录状态同时显示带标签的 `userSubject`、目标系统账号和已验证主体，避免把 `guomao` 或 `yanshi` 单独称为当前“账号”。

### P2 下游数据异常提示

完成率超过 100% 时应保留原值，同时显示“下游数据异常，建议核对”，不能静默纠正或当作普通进度。
