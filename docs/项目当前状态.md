## 1. 当前结论

AgentBridge 已从早期浏览器扩展原型演进为可运行的中心端、多系统、多用户、多端智能体能力平台：

- 最终用户设备不安装遗留系统连接器、Chrome 扩展或本地 AgentBridge daemon；
- OpenClaw 等宿主通过 HTTPS MCP 调用中心 AgentBridge；
- `agentbridge.host.v1` 已把 OpenClaw 从协议事实来源收敛为 Host Adapter，并提供独立 Python
  Reference Host 证明同一中央能力可由第二宿主调用；
- 登录、业务字段填写和最终授权通过模型循环之外的可信卡完成；
- Telegram、微信和独立 Agent Workspace 可使用同一用户主体接续任务、同步状态、展示卡片和交付文件；
- 多个真实用户使用独立 Token、身份绑定、系统会话、浏览器 Profile、操作账本和通道路由；
- 所有正式写入都经过冻结计划、独立授权、单次提交和权威回读，结果未知时停止且不自动重试；
- 跨系统目标可以形成中央持久任务计划，按公共能力、注册转换和一个受控写入终点执行，等待可信交互或重启后从权威步骤续办；
- Chrome 扩展、旧浏览器桥、localhost daemon 和代理型 CLI 已整体退役。

当前阶段仍是受控内网 PoC/试点基线，不等同于企业级生产平台。每用户独立 OS/容器 Worker、
企业 OIDC/OBO、Vault/KMS、正式 PKI、高可用和异机灾备仍在路线图中；试点 SLO、运行事件和
一致性备份已经进入运行治理基线。

2026-09-05 文档与代码交叉审查后的五类缺陷已完成修复：计划取消与授权消费共用 SQLite 事务边界，
字段/授权续办和最终提交复核原计划执行权限及冻结版本；独立计划拥有独立步骤幂等键，迁移前在途
计划保留原键；泰华日志与照明备注在提交边界后的非权威异常进入结果未知，禁止自动补发。已取消
计划的旧字段卡和授权卡失效。发布与测试结果统一记录在[本轮修复验收](./验收记录/持久计划与受控写入边界修复验收-2026-09-05.md)。

针对笔记本频繁盒盖和跨地点换网，启动器还会识别超过 60 秒的系统暂停，主动废弃睡眠前连接；
在线状态每 15 秒更新心跳，213 通过 SSH `ClientAliveInterval 5/ClientAliveCountMax 2` 回收未正常
关闭的旧反向会话。Guard 能区分“任务仍是 Running”和“隧道真实在线”，异常恢复只作用于隧道，
不重启健康的 Gateway。
中心端默认提供 60 秒受理前持久等待，连接恢复按 `1、2、3、5、8、10...` 秒退避；受理后只
观察和核对同一 `runId`，不因连接中断重投原请求。

会话保活间隔为 10 分钟，活动租约为 7 天。后台探测只维持仍在租约内且可续期的会话，
不会把已被下游明确注销的会话伪装为有效。

运行治理二期已加入持久化 Trace、Span、Signal、Incident、SLO 和 RecoveryAction，异常检测
使用独立于会话保活的后台周期。管理端可以查看端到端阶段时间线、运行事件和恢复账本，并且只
允许重投已确定通知、归档投递和重新评估运行状态。每日一致性 SQLite 备份由独立 systemd timer
执行，备份创建时立即做完整性、必要表和跨用户关联检查。Windows OpenClaw Gateway 与 Workspace
隧道已具备任务计划自愈；Gateway 的人工重启、发布重启和异常恢复统一使用可见前台生命周期
控制器，守护器会识别 180 秒内的冷启动、重复实例、失效锁和“后台仍活着但前台窗口消失”的
情况。生命周期控制器与 Guard 共享带心跳和 TTL 的启动租约，慢启动期间不再发生第二个恢复动作，

## 5. 写操作治理

面向智能体公开的是业务意图，例如“提交出差申请”或“审批补签申请”，不是底层 HTTP、DOM、
选择器或 commit 工具。标准链路为：

```text
用户意图
  -> prepare / 读取实时业务状态
  -> 可信字段卡（需要补充字段时）
  -> 冻结计划与独立授权卡
  -> 内部 commit（对模型隐藏）
  -> 权威回读 / 明确成功、失败或 unknown
```

跨用户、跨会话、过期、字段漂移、目标漂移、重复消费和权限不足均失败关闭。可逆动作提供明确
补偿能力；不可逆动作必须单独标记，不因存在通用写权限而自动开放。

补签接收处理已增加批量受控编排一期。用户表达“处理所有补签申请单”时，中心端一次冻结当前用户的
候选待办，每项仍独立填写和授权；当前项经 OA 权威回读成功后自动出现下一张卡，不再要求用户发送
“继续”。批次由一个父任务持久化，明确失败、拒绝、过期或结果未知时保守停止，多端重复回调不能跳项。
宿主主链与伴随端通知现在共享续办占位；父任务终态会主动清除残留轮询，中心端拒绝为终态任务续发协调
租约。迟到的卡片完成通知因此只被确认并忽略，不再在成功结果之后追加虚假的 `RESUME_FAILED`。

跨系统持久计划与补签批量编排是两种不同机制：前者组合不同系统的公共原子能力和注册转换，后者
处理同一流程类型的多条冻结事项。二者都复用 Task Hub 和可信写入，但不会互相代替。
