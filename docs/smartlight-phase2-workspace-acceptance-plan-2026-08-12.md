# 照明系统二期 Workspace 真实验收计划

## 一、目的与当前缺口

本计划补齐照明系统二期在 Agent Workspace 浏览器端的真实用户验收。

此前已经完成：

- 二期 A 五项能力的真实 MCP 数据验证；
- 二期 B 四类 CSV 的真实 MCP 调用和 HTTP 文件下载验证；
- Workspace 任务、文件卡、过期状态和重新生成的自动化测试；
- AgentBridge、Workspace、OpenClaw 的部署与健康检查。

此前没有完整执行“在 Workspace 输入自然语言 -> 观察流式过程 -> 查看任务与卡片 ->
浏览器下载文件 -> 刷新后恢复”的端到端真实验收。本计划专门验证这最后一公里。

## 二、范围与安全边界

- 验收身份：第一用户辛国茂。
- 验收入口：Agent Workspace 网页端。
- 目标系统：照明实验室测试系统。
- 只执行读取、分析和 CSV 报告导出。
- 不执行设备控制、参数配置、告警处置、巡检打卡或其他业务写入。
- 登录过期时允许使用照明系统可信登录卡；密码和验证码不进入聊天或测试记录。
- 第二用户只做未授权与数据隔离检查，不调用第一用户会话。

## 三、证据与判定方法

每轮同时核对四层证据：

1. Workspace 页面：用户消息、流式回复、任务状态、文件卡和刷新后的恢复结果。
2. Workspace API：任务、事件时间线和产物数量。
3. OpenClaw：每条请求的 run、工具调用次数、重复调用和异常。
4. AgentBridge：能力调用、会话身份、服务错误和任务终态。

通过标准：

- 页面无错误弹窗、无重复卡片、无长期进行中的任务；
- 每个自然语言请求只执行一次必要业务能力；
- 页面结果与后台结构化结果一致；
- 每份 CSV 只有一个有效产物，文件可下载且内容契约正确；
- 页面刷新不会丢失消息、任务或产物；
- 第一用户数据不会出现在第二用户 Workspace。

| 编号 | Workspace 请求或动作 | 预期结果 |
| --- | --- | --- |
| W0-1 | 检查照明实验室测试系统登录状态 | 身份为辛国茂；有效会话不弹登录卡 |

### W1 二期 A：资产详情与分析

| 编号 | Workspace 请求 | 核心检查 |
| --- | --- | --- |
| W1-1 | 查找照明系统中的 RTU，列出前 5 个 | 返回精确 ID、名称和状态 |
| W1-2 | 查看上面第 1 个 RTU 的详细信息 | 正确承接上文，返回继电器和回路 |
| W1-3 | 分别查找控制柜和灯杆并查看首项详情 | 三类资产均可查询和读取详情 |
| W1-4 | 分析最近 30 天 RTU 告警 | 总数、分析数、截断、趋势和排行口径一致 |
| W1-5 | 查看巡检任务并读取第 1 个任务每日进度 | 正确解析任务 ID，不编造未巡设备 |

### W2 二期 B：四类 CSV 报告

| 编号 | Workspace 请求 | 核心检查 |
| --- | --- | --- |
| W2-1 | 导出最近 30 天 RTU 告警分析 CSV | 单一文件卡、任务完成、CSV 可下载 |
| W2-2 | 导出最近 30 天漏电分析 CSV | 行数与报告元数据一致 |
| W2-3 | 导出全部 RTU 资产清单 CSV | 中文文件名、表头和数据完整 |
| W2-4 | 选择一个巡检任务，导出每日进度 CSV | 自动取得真实任务 ID 并生成文件 |

每份文件必须满足：

- `Content-Type` 为 `text/csv`；
- 具有 UTF-8 BOM，中文 Windows/Excel 可直接打开；
- CSV 非空，行数等于数据行数加一行表头；
- 页面只出现一张对应文件卡；
- 文件卡显示文件名、大小、下载状态和有效期；
- 任务进入已完成状态。

### W3 页面状态、顺序与恢复

| 编号 | 动作 | 预期结果 |
| --- | --- | --- |
| W3-1 | 报告生成后刷新页面 | 消息、任务和文件卡仍存在且顺序不变 |
| W3-2 | 切换任务后返回 | 原任务上下文和产物完整恢复 |
| W3-3 | 运行中快速发送第二条请求 | 明确拒绝、排队或提示已有任务，不重复执行 |
| W3-4 | 检查事件时间线 | 用户消息、处理中、结果/卡片、完成按序且不重复 |

### W4 文件过期与重新生成

测试开始时生成 W2-1；自然等待至少 30 分钟后：

1. 刷新 Workspace，原文件卡继续存在并显示已过期。
2. 点击“重新生成下载”。
3. 原卡原位恢复为可下载，不生成重复任务或重复文件卡。
4. 新文件使用原查询条件重新读取当前数据。
5. `artifactId` 保持不变，下载源、生成时间和有效期更新。

| W5-3 | OpenClaw 调用日志 | 每个报告请求只有一次 `smartlight_report_export` |
| W5-4 | AgentBridge 任务与产物 | 所有测试任务终态正确，每份报告一个产物 |
| W5-5 | 服务健康与错误日志 | 服务正常，无本轮新增未解释错误 |

## 六、完成条件

核心验收要求 W0、W1、W2、W3 和 W5 全部通过。W4 需要自然等待 30 分钟，可与其他
轮次并行；若本轮时间窗口不足，必须保留起始报告和开始时间，达到有效期后再补做，不能
用直接修改生产数据库代替真实过期过程。
