# OA 会议室读取能力

## 一、能力边界

OA 的“会议”和“会议室”是两个相关但独立的业务域：

- “会议”负责主题、时间、参会人、正文以及创建发送；
- “会议室”负责会议室目录、容量、是否需要审核、时段占用和本人会议室申请；
- 会议室申请的撤销、提前结束和催办审核属于会议室写操作，本期未开放。

现有 `oa.meeting.create.prepare` / `oa.meeting.create` 仍是会议写能力。新增读取能力不替代它们，
而是作为会议创建前的统一事实来源。

## 二、公开能力

### 1. 会议室目录和时段占用

MCP 工具：`oa_meeting_room_availability_list`

中心能力：`oa.meeting_room.availability.list`

支持条件：

- `start_time`、`end_time`：必须同时提供，按上海时区解释；
- `room_name`：按会议室名称筛选；
- `minimum_capacity`：按座位数筛选；
- `only_available`：只返回指定时段空闲的会议室；
- `limit`：限制公开结果数量。

未提供时间时只列会议室目录，不声称会议室当前空闲。提供完整时段后，输出每个会议室的
`available` 和与查询区间重叠的占用时间段。占用结果不公开会议主题、申请人或参会人员信息。

底层事实来源为会议室模块的 `meetingAjaxManager.roomListInfo`，不是“新建会议”页面的临时选项。

### 2. 我的会议室申请

MCP 工具：`oa_meeting_room_my_applications_list`

中心能力：`oa.meeting_room.my_applications.list`

支持把以下条件直接下推给 OA：

- 会议室名称；
- 申请日期范围；
- 审核状态：`pending`、`approved`、`rejected`；
- 返回数量上限。

结果来自“会议室 > 我的申请”的 `meetingAjaxManager.getMyApps`，包含会议室、会议名称、申请时间、
使用时间、审核状态和使用状态。该集合不是 OA 已发事项，也不是会议列表。

## 三、会议创建复用

会议创建现在复用会议室读取模块的 `roomListInfo` 快照和会议室匹配、冲突判断逻辑：

1. 用户询问会议室时，读取工具查询真实目录和占用；
2. 用户发起会议创建时，填写卡再次读取同一会议室事实源并预填空闲选项；
3. 字段提交后、授权前再次校验；
4. 用户授权后、进入写边界前再校验一次；
5. 创建发送后仍用会议室占用和会议详情双回读确认结果。

查询结果只是时点快照，不能代替写入前复检。其他人可能在查询和授权之间占用会议室，因此会议创建
仍会在写边界前失败关闭，不会凭旧查询强行提交。

## 四、安全与权限

- 两个新工具均为只读能力，只要求 `oa:read`；
- 不创建会议、不提交会议室申请，也不点击撤销、提前结束或催办；
- 用户身份由中心会话绑定，两个用户的会议室可见范围和“我的申请”结果相互隔离；
- 时间范围、审核状态和名称筛选由适配器校验，不接受任意底层接口参数；
- `coverage.status=partial` 时不得把返回结果描述成完整集合。

## 五、人工验收提示词

可以在 Workspace、Telegram 或微信中依次发送：

1. `查看 OA 有哪些会议室。`
2. `查明天下午 2 点到 4 点空闲的 OA 会议室。`
3. `查明天下午 2 点到 4 点能坐 20 人的空闲会议室。`
4. `查看我的会议室申请。`
5. `查看本月审核通过的会议室申请。`

前 3 条应调用会议室目录/占用工具；后 2 条应调用“我的申请”工具。整个验收不应出现字段卡或授权卡，
也不应产生会议、会议室申请或 OA 流程写入。
