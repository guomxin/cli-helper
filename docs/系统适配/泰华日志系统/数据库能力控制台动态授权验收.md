# 数据库能力控制台动态授权实施与验收

日期：2026-09-12。

## 已实现

按《数据库能力控制台动态授权设计》先落文档，再实现。管理控制台“用户与令牌”可查看和配置每个中央账号的七项独立数据库能力；自由只读 SQL 单独列为高级选项。空列表可撤销全部授权，保存要求填写原因并比较配置版本，避免覆盖其他管理员的更新。审计员仅能查看。

能力仍由中央账号识别，每次数据库调用读取最新授权，不映射数据库人员 ID。此次修改不涉及 OpenClaw 插件、Token 签发或撤销、宿主配置。授权变更与数据库授权审计同事务保存，并写入管理审计。

同时补上管理接口缺失 CSRF 请求头时的拒绝逻辑；此前 None 会使会话验证跳过 CSRF 比较。窄屏弹窗固定标题和操作按钮，中间内容可滚动。

## 本地验证

- 管理接口、独立数据库和内容分析：40 项测试、80 个子测试通过。
- 新增集成测试使用真实本地管理 HTTP 服务、两个中央账号预先签发的原 Token 和同一 MCP 服务实例。管理接口启用七项能力后，两账号均可调用；撤销 guomao 后执行拒绝且不进入查询，lishiyu 不受影响；恢复后原 Token 继续可用。底层 SQL 执行使用桩，此项不是生产数据库验收。
- 未登录、审计员写入、错误或缺失 CSRF、错误 Origin、未知账号、无效能力与版本均拒绝；旧 revision 返回 409；成功操作的前后状态和审计数量一致。
- 隔离 Chromium 测试验证管理员勾选保存、重开回显七项、审计员七项禁用、1280px 和 390px 布局无横向溢出、窄屏标题及保存按钮可见。截图在 output/admin-database-grants-20260912/。
- 原有控制台全视图浏览器测试首次运行失败，输出伴随本地静态资源连接中断；单独重跑通过。新增授权浏览器测试通过。
- 文档检查：7 项测试、690 个子测试通过。

## 线上配置与 Workspace 状态

用户已指定 guomao、lishiyu 均启用全部七项能力，包括高级自由只读 SQL。此最终授权范围仍须在真实管理控制台保存，再通过两个账号的 Workspace 实测。

当前 Chrome 工具初始化返回 `failed to write kernel assets` / `os error 3`，在页面发现前失败。已核对 Chrome 扩展启用及 Native Messaging 注册正常；重连扩展后错误未变化。不能据此判断 Chrome 登录态失效。

真实控制台授权保存、Workspace 查询、同一 Workspace 中撤销与恢复仍为**未执行**，不得用上述隔离测试替代。恢复工具后继续复用 Chrome 扩展和现有登录态，分别核对账号，完成验收并恢复两账号七项最终授权。
