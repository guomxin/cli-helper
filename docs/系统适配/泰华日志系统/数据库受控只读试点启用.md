# 数据库受控只读试点启用

2026-09-09：用户明确选择使用现有数据库账号试点。此策略不修改源数据库权限，不等于数据库账号已完成最小权限收敛。

## 准入策略

`analytics/source.json` 新增 `privilege_policy`，默认 `strict`。显式设置为 `controlled_readonly_pilot` 时，TEMP、public 序列 USAGE 作为风险提示允许通过；特权角色、表/列写权限、public 序列 UPDATE 仍拒绝。未知策略拒绝。只读事务、重复读隔离、超时、固定参数化 SQL、API 前后可见性与数据一致性校验均保留。

试点账号仍可能直接读取非分析所需表。服务端执行器只查询 work_log 的指定列及元数据，不提供任意 SQL 或任意表读取工具。认证表读取范围与未来默认授权仍是 DBA 后续收敛事项，不应将 `privileges_reviewed` 理解为源库权限已撤销。

在此策略下 `privileges_reviewed: true` 表示管理员已核对实际权限并按用户明确授权接受试点剩余风险。每次汇总的 provenance 保存 privilege_policy 和 privilege_warnings；检查命令也输出这些字段。严格策略含义不变。

## 启用步骤

1. 部署已验证版本，保留加密凭据与关闭状态；核验单实例部署。
2. 配置试点策略并运行 `python -m bscli.analytics.admin --home /home/guomao/agentbridge/data check`，只读核验数据库最小契约。
3. 确认 guomao 对应辛国茂的日志系统会话有效，仅为该身份现有 Token 增加 taihua:analytics:read 和 taihua:analytics:export。
4. 配置 admitted_subjects 为 `["guomao"]`，privileges_reviewed 和 enabled 为 true，进入受限验收；如真实取数不通过立即关闭 enabled。
5. 通过认证 MCP 验证本人非空窗口、结果重读、周期比较和 CSV 下载；校验窗口条数、工时与覆盖状态。普通用户未验收时不扩大名单。

配置文件不得包含明文密码。启用前保留原配置及 Token Scope 备份，回退时先关闭 enabled；必要时恢复本次增加的两个 Scope，保留其他原有权限。

旧的开发记录中“未部署”属于当时状态；本次部署与真实验收结果以新的生产试点验收记录为准。
