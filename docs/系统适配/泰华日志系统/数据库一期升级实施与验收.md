# 数据库一期升级实施与验收

日期：2026-09-12。设计依据：[数据库一期升级设计](数据库一期升级设计.md)。本记录描述实现与发布前检查，线上发布状态由本次发布流程的验收记录确认。

## 已实现

1. 正文查询增加字面关键词（单词或多词 any/all）、当前部门筛选、匹配片段与来源 ID；统计使用同样条件。旧明细默认倒序 200 条、DAILY 及可空 user_id/project_id 兼容。
2. 新增 database.logs.content_analyze，统一支持总结、主题、进展、问题、经验、协作、变化七种模式。服务端返回证据及分析要求，由当前智能体完成语义归纳，不调用额外模型供应商。
3. 新增 database.comments.analyze，支持反馈、问答、跟进三种模式；明确日志作者、评论作者、评论日期与日志日期。返回评论及关联日志来源。
4. 明细及分析证据支持游标分页、完整筛选范围的 total_matching、has_more 与 next_cursor。游标绑定能力、模式、条件和排序，最后一页不宣称已读完此前各页。跨请求不承诺冻结快照。
5. 能力目录提供 input_schema；MCP、中央规划规则、OpenClaw 工具目录已同步。OpenClaw 插件版本升级到 0.4.93，保留旧 0.4.92 兼容记录。

正文与评论作为不可信数据，原文保留，阅读文本清理脚本和样式；结论按来源引用。现有中央 Token 机制及生产能力授权不变。自由只读 SQL 仍独立覆盖五视图，包括评论。

## 调用示例

先调用 database_capabilities，以实际返回的能力及 input_schema 为准。以下为 database_execute 参数，不代表账号自动获准。

正文检索：

```json
{"capability":"database.logs.query","arguments":{"start_date":"2026-08-31","end_date_exclusive":"2026-09-07","keywords":["项目","付款"],"keyword_mode":"all","page_size":50}}
```

日报周总结：

```json
{"capability":"database.logs.content_analyze","arguments":{"start_date":"2026-08-31","end_date_exclusive":"2026-09-07","mode":"summary","page_size":50}}
```

评论跟进：

```json
{"capability":"database.comments.analyze","arguments":{"start_date":"2026-09-01","end_date_exclusive":"2026-09-12","date_basis":"comment_created_at","mode":"followup","page_size":50}}
```

继续读取时保持同一能力、模式和筛选条件，将上一页 next_cursor 对象原样放入 arguments.after。按 evidence_id 去重并核对 total_matching；未读取完或数据发生变化时说明覆盖限制。结果证据准备好不等于语义回答已生成。

## 交付边界

此轮完成独立只读数据库内容能力升级。新增能力未自动授予 guomao 或 lishiyu；生产可用范围以各账号 database_capabilities 实际结果为准。授权 UI、语义索引、结果历史/CSV、多引擎、提醒任务和数据库写入均不在本轮范围。

语义总结的质量依赖当前智能体实际读取的证据和归纳；本轮自动化验证证明取数、分页、授权及证据契约正确，不宣称对所有真实日志的总结质量已做全量人工验收。
