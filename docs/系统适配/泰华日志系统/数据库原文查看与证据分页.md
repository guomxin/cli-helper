# 数据库原文查看与证据分页

## 使用方式

日志查询和内容分析返回作者、日期组成的 `source_label` 与 `source_url`。智能体在结论旁展示可点击的来源；内部 `evidence_id` 保留用于核对和去重。原文页由 AgentBridge Workspace 提供，直接读取已配置的日志数据库，链接可追加 `#paragraph-N` 定位段落。

无需修改原日志业务系统或接入它的详情 API。没有配置 Workspace 地址时 `source_url` 为空，调用方不得编造链接。

## 原文与权限

- 页面：`/database/logs/{source_id}/{log_id}?revision={正文版本}`；数据接口：`/api/database/logs/{source_id}/{log_id}`。
- 使用当前 Workspace 登录账号的中央主体，仅允许拥有此数据源 `database.logs.query` 或 `database.logs.content_analyze` 的账号读取。统计、评论或自由 SQL 授权不自动取得此入口权限。
- 每次读取检查数据源状态、授权版本与会话；已有链接不构成授权。未登录、权限不足、授权变化、记录不存在均明确提示。数据响应禁止缓存。
- 展示数据库当前文字、作者、日期、当前部门、来源、可用的更新时间及读取时间。正文按纯文本渲染，日志中的 HTML/脚本不执行。
- 版本基于规范化正文生成；正文变化时提示并停止旧段落高亮。该入口不保存历史快照，也不还原历史人员归属；格式变化而文字不变不视为正文变化。评论来源链接仅指向关联日志。

## 正文分页协议

标准日志明细和内容分析增加 `log_id` 精确读取，可不传日期，不默认排除周报。原有按时间查询仍须传起止日期。

`max_chars` 默认 12000，可取 4000–14000，按完整 JSON 的 UTF-16 字符数预算响应，为宿主包装留出空间。普通调用省略该参数，不主动选最低预算。`evidence_format=compact` 为默认；明细查询和内容分析都将正文保留在 `passages` 中，减少同一正文重复传输。`full` 用于需要兼容完整字段的调用方，仍受容量限制。

普通响应保留来源、查询标识、SQL 摘要、实际范围与分页信息；SQL 全文、列清单、重复说明及完整查询条件通过 `include_diagnostics=true` 按需获取。超过 20 个部门的范围默认提供根部门、成员数量与完整范围指纹；游标仍绑定完整成员，未减少实际查询范围。诊断响应也受容量上限约束。

记录超过响应容量时，按条数减少本页并返回 `has_more`、`next_cursor`；游标仍绑定筛选条件与已核验部门范围。数据库按小批次读取正文，并保留下一条记录用于判定是否还有数据，避免大量长正文在分页前触发大小限制。

单篇日志过长时返回正文片段，包含 `text_offset`、`next_text_offset`、`total_text_chars`、`content_complete=false`。调用方通过同一能力、`log_id`、同一分析模式（如适用）、`text_offset=next_text_offset`、`expected_revision=source_revision_hash` 续读，直到 `next_text_offset=null`，再合并片段。非首片段的 `content_complete` 仍为 false，表示该响应单独不包含整篇正文。续读期间正文变化明确拒绝，不能混合两个版本。

只有记录页和正文片段都读完才算读取完成；不同请求不是冻结快照。单条源记录仍受既有后端 1 MiB 结果保护；元数据或评论上下文无法放入预算时明确报错，不静默丢弃。CSV 导出保留既有独立导出限制。

## 总结契约与验证边界

明细查询与内容分析共用 `analysis.review_contract` 和本页 `coverage_manifest`：先拆分每篇所有独立事项（同段可有多项），保留来源段落、原文状态用语与摘要去向，再归并并逐条核对来源。计划、进行中、已完成、问题与未知必须区分；未覆盖事项须补充或说明省略理由。清单是复核辅助，不是语义正确性的自动证明。

## 能力发现与失败恢复

MCP `database_capabilities` 默认只返回有权限的来源和能力摘要，使用 `after_source_id=next_after_source_id` 翻页。以 `source_id` 和 `capability` 获取单项完整 `input_schema`，避免把所有结构及重复兼容字段一次送入宿主而被截断。内部管理目录保持原接口。

拒绝响应保留原错误码并增加 `recovery`。容量不足时，仅建议 `max_chars`、`include_diagnostics` 的补丁；调用方合并补丁时保留来源、能力、日期、部门、其他筛选和游标，不反复缩小页大小，也不切换自由 SQL。参数错误重新取单项结构；权限变化重新检查授权；组织范围或正文版本变化从对应起点重读。仍无法容纳的响应明确返回 `capacity_limit`，不得声称已完成读取。

回归覆盖多来源目录、单项结构、两种正文读取能力的 4000/6000/12000/14000 预算、诊断元数据超限恢复、组织游标、长单篇连续读取及版本变化、原文权限与会话入口。`scripts/verify_database_evidence.py` 可使用既有主体授权，按 `--capability`、`--max-chars`、`--department-id`、`--log-type` 对真实数据分页及原文逐条核对；不创建或修改业务日志、不扩大授权。部署前运行固定发布入口的 `-PlanOnly`，工具目录说明变化需要按运行时差异判定重启 OpenClaw。
