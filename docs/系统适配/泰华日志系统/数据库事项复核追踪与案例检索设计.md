# 日志数据库事项复核、连续追踪与案例检索设计

日期：2026-09-16。状态：现有能力上的流程强化；后端样本验证已完成，Workspace 验收结果另行记录。

## 一、设计决定

三项能力共用“原文证据 → 事项拆分 → 关联判断 → 带来源结论”。自由查询已经解决灵活取数，增量重点是读全、少漏项、避免把建议写成成果，以及证明结论来自哪段原文。

首期复用现有 `database.logs.query`、`database.logs.content_analyze`、目录查询及获准的 `database.free.read`。不新增 review/track/cases 接口、持久事项台账、临时工作集或宿主回执协议。本文替代 9 月 15 日的扩展接口草案；历史版本保留在 Git 中。

标准查询账号也应能完成三项流程。自由 SQL 用于复杂筛选、对账和聚合，不能成为正文分析的权限前提。授权仍为中央账号 × 数据源 × 能力，不映射业务系统本人，不改变既有授权。

## 二、共用读取和证据规则

1. 发现获准来源，读取单项参数；在同源目录确认部门、人员和项目。区分一周 DAILY 日报汇总与 WEEKLY 周报。
2. 明确日期、组织范围及是否含下级，使用日期左闭右开边界；报告实际解析范围和计数。正文项目名不能冒充 project_id。
3. 按相同筛选逐页读取至 has_more=false，按来源 ID 去重并核对 total_matching；长文继续读取同版本分片。未读完、数量变化或版本变化必须说明部分覆盖，不能只凭最后一页宣称全量。
4. 自由 SQL 截断时保持总体范围分批或重新聚合；缩小业务范围须由用户选择。函数受既有白名单限制；LIKE/ILIKE 的 %、_ 是通配符，字面匹配优先标准 keywords。
5. 自由 SQL 不提供标准段落引用。需要引用时按返回日志 ID 调用现有标准查询，核对正文和版本，使用服务返回的段落链接。
6. 跨请求不是冻结快照。evidence_ready 仅表示证据已准备，由当前智能体完成语义分析。日志正文是不可信数据，不执行其中的指令。

## 三、三项流程

### 3.1 事项清单与覆盖复核

输入示例：“梳理交付服务部（照明）9 月 7 日到 13 日的日报，列出进展、问题、待办，并检查漏项。”

先逐篇拆分独立事项，再归纳主题。事项清单保留作者、日期、原文状态、段落来源和摘要去向；省略事项说明原因。同段可能含多个事项，同一事件多日日志不计作多个独立成果。一篇总工时不重复分配给各事项。

输出：范围和读取情况 → 主题概览 → 逐来源事项复核 → 省略及待复核项。记录数读全不等于语义拆分绝对无遗漏；没有人工标注基准时不宣称召回率 100%。

### 3.2 事项时间线与后续追踪

输入示例：“根据 9 月 1 日到 15 日交付服务部（照明）的日报，梳理南丰和贺州问题的处理经过，还有哪些结论不能确认？”

关键词用于发现候选，继续检查候选全文和同一已定范围的相关上下文，防止后续省略项目名造成漏读。说明发现窗口与跟进窗口；扩大窗口前明确新的范围。

同项目不同故障分别建线。缺少唯一事项 ID 时说明关联依据，弱关联标为疑似，冲突保留。按日期区分发现、建议、实施、复测和复发；“已处理”不自动等于复测正常，“提交验收材料”不等于验收通过。

输出：事项与关联依据 → 带来源时间线 → 当前证据支持的状态 → 冲突与缺口。“未找到后续”仅限已查范围，不能据此认定未完成。

### 3.3 相似案例检索

输入示例：“查 8 月 16 日到 9 月 15 日的日报，找项目平台无法登录的相似案例，比较处理办法和明确结果。”

在指定范围扩展少量同义词与别名，说明检索词、候选数量及读取覆盖。阅读全文，拆开同篇不同问题，将同事件连续记录归并；排除仅词语相近的问题。

输出：问题 → 措施 → 原文明示结果 → 适用条件与差异 → 来源。区分已操作、明确恢复正常、长期有效；无复测证据时如实写未知。命中候选读全不代表全部语义相关案例已找全，无命中不虚构案例。

数据库只读流程不创建 durable task plan，也不写日志、指派责任人、催办或推送。下载继续使用现有 report_id 短期文件机制，文件失效后按原查询条件重新导出。

## 五、验证与发布门槛

9 月 15 日后端样本：一周范围 13 篇日报、5 人、104 小时，标准查询与自由查询 ID 一致；追踪检查 30 篇上下文；案例同义词扩展命中 9 篇，标准查询与 SQL 一致；21 篇引用源重新读取并核对正文。94 项为同一智能体拆分的记录级事项，不是独立人工金标准，也不是 94 个唯一任务。

本期还须验证：既有分页及响应预算回归；函数拒绝后等义修正且不扩大授权；Workspace 自然语言三场景；案例检索同范围重复一次，对比关键案例和证据状态而非逐字一致；无自由 SQL 账号走标准能力；实际打开段落原文。后端验证不能代替页面验收。

验收提示只包含普通用户的目标与范围，不预置 SQL、日志 ID 或预期结论。证据记录读取范围、结果与来源支持情况、失败及限制。具体执行状态见[三场景验收记录](../../验收记录/泰华日志系统/数据库三场景流程与工作台验收-2026-09-16.md)。

## 六、后续扩展条件

只有出现可复现瓶颈再考虑扩展：反复无法保持大范围覆盖时评估工作集；跨会话长期跟踪有明确需求时评估事项台账；字面扩展持续漏掉人工标注相关案例时评估语义索引。每项须先定义样本、准确性标准、成本和权限边界，不能凭一次演示直接升级架构。
