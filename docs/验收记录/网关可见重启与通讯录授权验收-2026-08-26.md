# OpenClaw 网关可见重启与通讯录授权验收

> 日期：2026-08-26
>
> 范围：Windows 本机宿主重启治理、第一用户 OA 通讯录授权
>
> 业务副作用：未读取待办列表，未执行任何业务写入

## 一、问题与原因

历史重启混用了 OpenClaw 原生任务、原生 `gateway restart`、隐藏子进程和外部 CLI 状态探针。
原生命令结束后可能遗留脱离外层任务的 Node 子进程和失效锁；Gateway 已响应 RPC 时，状态 CLI
仍可能因插件运行时未退出而长时间等待。旧计划任务还会以隐藏方式启动，因此“端口正常”不代表
用户能在前台看到 Gateway。

## 二、收口实现

- 原始启动命令保存在 `%LOCALAPPDATA%\AgentBridge\openclaw-gateway-runtime.cmd`；
- `Restart-AgentBridgeOpenClawGateway.ps1` 负责停止、等待、失效锁清理和可见 Windows Terminal 启动；
- 人工重启、发布重启和守护自愈使用同一控制器；
- `AgentBridge OpenClaw Guard` 同时检查单进程、单监听和可见前台父窗口；
- 就绪验收使用 `/readyz`，插件验收使用本次启动的结构化注册日志和仓库清单版本；
- 不再把 `openclaw gateway status` 或 `plugins inspect` 的进程退出当作重启完成条件。

## 三、真实结果

一次完整重启将旧 Gateway PID `18648` 替换为 `3004`，清理一份仅属于失效 PID 的锁文件，
最终 `18789` 只有一个监听，`/readyz` 正常，插件 `agentbridge-interactions` 以 `0.4.59` 注册，
Windows Terminal 前台窗口可见。随后执行 `-StartOnly` 返回 `already_running`，没有创建重复实例。
守护任务接管后报告单 Gateway、可见前台、隧道无动作、错误为空。

第一用户正式 Token 已包含 `oa:read:addressbook`，真实组织查询成功；被替换的第一用户旧 Token
随后撤销。第二用户仍保留原活动 Token 和原权限范围，没有签发、撤销或扩权。

## 四、验收结论

通过。今后 Gateway 重启统一执行：

```powershell
.\scripts\Restart-AgentBridgeOpenClawGateway.ps1
```

重启后必须同时看到前台窗口、`/readyz=ok`、唯一监听和当前插件注册；缺一项都不算完成。

## 五、命令窗口收口与通讯录复核

后续复核发现，交互式计划任务即使使用 `powershell.exe -WindowStyle Hidden`，仍会创建 Guard
控制台宿主；Gateway 被受控终止时返回非零退出码，还会使 Windows Terminal 保留已经失效的旧
标签页。两者叠加后，用户会看到第三个命令窗口，但后台并没有第二套 Gateway 或第二条 SSH 隧道。

现已将 Guard 改为通过 `wscript.exe` 无控制台包装器启动，并让 Gateway 前台包装器退出时返回
成功，由 Guard 继续记录和恢复实际故障。连续两次真实重启后均只有一个活动 Terminal 会话、一个
Gateway 进程和一个 `18789` 监听，Guard 与 Workspace 隧道保持单实例。此前遗留的一条只读 SSH
诊断进程也已清理。

第一用户随后完成通讯录真实复核：组织树返回 48 个可见组织；“照明市场推广中心”和“智能照明
运维中心”分别返回 4 人和 2 人；两次按姓名查询均唯一命中。查询“公司里面谁职位最高”目前依据
OA 组织架构中的“董事长”组织进行推断，不代表系统提供了通用职级排序接口，回答应保留这一边界。
