## 二、修复与断言

| 问题 | 修复 | 自动化判据 |
| --- | --- | --- |
| 取消与提交竞态 | 同一 SQLite 事务竞争取消与授权消费；持久化提交 Operation 标记；取消后旧卡失效 | 取消先返回成功则授权不消费；提交先进入边界则拒绝取消，保留最终核验结果 |
| 原计划授权撤销仍可续办 | 字段、授权续办和最终提交均核对原快照及全计划 Scope | 另一枚同用户有效写 Token 不能绕过原 Token 撤销、过期或缩权；提交前再次撤权也不越界 |
| 写后异常被当作普通失败 | 泰华日志和照明备注分清明确拒绝与应答/回读异常；中央提交增加 unknown 兜底 | 提交和回读网络错误进入 `RESULT_UNKNOWN`；未知操作不重新调用业务提交 |
| 相同新计划复用旧 Operation | 新计划按实例和版本持久化键前缀；旧在途计划兼容原键 | 同内容两个新任务各读一次，同一请求重放复用原结果；旧键恢复不多读一次 |
| 冻结版本未执行 | 执行、续办及恢复核对能力/转换版本；旧 Operation 按冻结版本查找 | 版本变化或转换消失时在业务调用前停止；已越界的恢复先核对原提交结果 |

重启故障注入分别覆盖“已消费授权但原 Operation 未完成”和“已留存成功核验结果”：前者进入待对账，
后者完成原计划，两者都不重放业务写入。提交等待期间的重复计划推进只返回等待核验。

主要回归文件为 `tests/test_plan_write_boundaries.py`，并保留授权、字段卡、计划存储、计划运行时、
中央服务和四系统现有回归。
