# 登录后查询续办修复验收

日期：2026-09-03。代码候选：本文件所在提交；插件：`0.4.79`。

## 一、故障事实

第一用户在 Workspace 发起“查看OA待办”，09:27:03 查询返回 `LOGIN_REQUIRED`，
09:27:27 可信认证已完成，但原任务没有再次查询 OA，也未结束。
原任务为 `106c060b-9c05-43b8-a5a3-c04f1dac9356`。

故障不是本次密码错误，也不是单纯的页面卡片刷新问题：

1. 旧只读续办只发送任务编号，漏掉 `io.agentbridge/host-context` 和协调租约版本，
   被现有正式宿主校验拒绝。
2. 失败反馈退回模型心跳，日志里出现 `HEARTBEAT_OK`，没有再次执行原查询。
3. 查询描述只保存在插件内存。Gateway 重启后只能恢复“登录完成”，不能恢复准确读取参数。

## 二、实现边界

- 不新增业务能力、命令、公共续办工具或工作流引擎。
- 利用操作账本对读取参数的完整持久化，查找同用户、同任务中紧邻认证卡之前的操作。
- 仅恢复注册为读取、同系统且明确因 `LOGIN_REQUIRED` 中断的操作；写入摘要不作为可执行参数。
- 组合计划继续由计划执行器管理；批量任务继续由批量协调器管理，不被单项查询恢复提前结束。
- 复用宿主私有 `agentbridge_interaction_resume`，保留当前 Token 权限、宿主等级及协调租约检查。
- 续办幂等键绑定原操作和认证交互，不因回调次数或 Gateway 重启变化。
- 查询结果先写中央时间线及同用户消息发件箱，再更新任务；网页通过 SSE 拉取，聊天端按既有可靠投递发送。
- 查询失败也生成明确结果并停止任务，不再无限心跳或等待用户猜测。
- 未绑定任务的兼容入口保留原有行为；兼容只读重试补齐正式宿主元数据、租约和已办/已发日期参数。
- 插件包、运行版本和宿主注册版本统一，并增加一致性回归检查。

## 三、自动测试

定向新增测试已通过：四类 OA 列表的准确参数恢复、日期与 `limit=1000` 保留、
重建服务后的恢复、重复和并发回调去重、消息持久化后的崩溃恢复、失败与再次失效反馈、
跨用户访问拒绝、终态任务停止、写操作不重放、长列表有界展示。

OpenClaw 覆盖恢复记录没有内存查询描述时的中央续办完成回执、成功或失败后不重复查询、
不重复发消息、不唤醒心跳，以及兼容入口正式宿主元数据和协调版本。
MCP 协议回归覆盖缺失宿主信息时拒绝、带完整宿主与协调上下文时允许。

最终完整回归通过：Python `798 passed, 3 skipped, 615 subtests passed`；
OpenClaw 插件 `172 passed`；Workspace 网关客户端 `24 passed`；依赖检查、文档检查与打包检查通过。
三个跳过项为既有跳过测试，不计为通过。细分权限覆盖通讯录读取，普通 OA 读取权限不能替代它。
线上发布与真实页面结果在完成后回填，不将离线模拟登录当成真实登录验收。

## 四、真实验收计划

1. 发布后从既有恢复队列接续上午已经认证成功的第一用户原任务，不主动退出用户 OA。
2. 检查原任务新增一次 `oa.workflow.pending.list`、原参数一致、任务成功结束、时间线展示待办结果。
3. 通过普通 Chrome 的第一用户 Workspace 发起“查看OA待办”，验证既有普通查询正常。
4. 核对原任务不再产生新的心跳回执或重复续办；核对本轮无业务写入。

不修改第二用户会话，不刻意使任何已登录会话失效，不新增或提交 OA/日志业务。
