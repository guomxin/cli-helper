# 通用持久化任务计划一期验收 2026-08-31

## 一、验收范围

本次验收验证通用持久化任务计划的一期主链路，不执行真实业务写入。验收目标是确认：

1. OpenClaw 能识别“读取业务数据后形成另一项业务成果”的组合目标；
2. 模型先读取按身份和 Scope 过滤的计划目录，再提交一份结构化计划；
3. AgentBridge 能确定性校验、持久化和执行读取与转换步骤；
4. Workspace 展示同一计划的真实步骤进度和终态；
5. 目录未声明的用户要求不会被臆造成步骤参数；
6. 整个验收不调用业务提交、私有 commit 或 resume。

验收环境：

- 中央 Release：`67d4af8f5a32`；
- OpenClaw：`2026.7.1`；
- `agentbridge-interactions`：`0.4.70`；
- Workspace：`https://10.10.50.213:8783`；
- 身份：第二试点用户，仅具备本场景所需的 OA 读取权限，不具备泰华工作日志写权限。

## 二、真实验收中发现的问题

### 2.1 模型绕过持久计划

初次页面测试中，模型直接调用 OA 已办读取，再自行组织文字；涉及日志填写时又单独调用泰华
`prepare`。业务能力本身可用，但没有形成可恢复、可审计的整体计划。

OpenClaw `0.4.68` 增加通用组合目标识别：同时出现数据来源和后续成果时，先调用
`agentbridge_task_plan_catalog`，再通过 `agentbridge_task_plan_prepare` 提交一份计划，不在宿主
中写入 OA 到泰华的专用业务流程。

### 2.2 步骤字段不可发现

原 MCP Schema 把 `steps` 暴露为 `list[dict[str, Any]]`。模型只能看到“对象数组”，看不到
`stepKey`、`capabilityName`、`transformName`、`dependsOn` 和 `bindings`，因此连续猜测多组错误字段。

OpenClaw `0.4.69` 对应的中央接口改为强类型步骤：

- `capability` 步骤必须使用 `stepKey + kind + capabilityName`；
- `transform` 步骤必须使用 `stepKey + kind + transformName`；
- Binding 明确使用 `step + pointer`；
- 未知字段由 Schema 和中央校验共同拒绝；
- 计划目录按当前身份返回合法且 Scope 安全的示例。

### 2.3 动态参数被错误扩展

步骤字段明确后，模型第一次仍把用户所说的“3 小时”放进
`work_items_to_log_draft.v1.arguments.hours`。该转换的 `inputSchema` 没有 `hours`，中央服务安全拒绝，
模型第二次修正后成功。该过程没有业务副作用，但不满足“一次形成合法计划”的体验目标。

OpenClaw `0.4.70` 在三处统一约束：

- 计划目录说明 `arguments` 只能使用对应 `inputSchema.properties` 声明的字段；
- MCP 工具说明要求未被 Schema 接受的用户要求留在 `goal` 或最终说明；
- OpenClaw 组合任务上下文禁止从用户措辞臆造参数。

## 四、Workspace 真实验收

最终提示词：

```text
计划验收 PLAN-ARGS-0831：汇总2026年7月的OA已办，整理成3小时工作日志草稿，只预览，先让我核对，不要提交。
```

页面结果：

- Workspace 创建一张持久任务计划卡；
- 计划从“执行中 1/2”推进到“已完成 2/2”；
- 第一步 `read_done` 调用 `oa.workflow.done.list`；
- 第二步 `draft_log` 调用 `work_items_to_log_draft.v1`；
- 两个步骤状态均为 `succeeded`；
- 风险投影仅包含 `oa:read`，`writeSinkCount=0`；
- 终态原因为 `no_eligible_source_items`：本次日期范围内返回的事项经转换规则过滤后没有可形成
  日志草稿的有效事项。这是确定的业务结果，不是计划执行失败；
- 用户给出的“3 小时”保留在计划目标中，没有作为转换器不支持的参数提交。

OpenClaw 权威会话日志从该用户消息起统计：

| 项目 | 次数 |
| --- | ---: |
| `agentbridge_task_plan_catalog` | 1 |
| `agentbridge_task_plan_prepare` | 1 |
| `agentbridge_task_plan_get` | 0 |
| 模型直接调用 OA 列表工具 | 0 |
| 模型直接调用泰华 `prepare` | 0 |
| 工具错误 | 0 |
| commit 调用 | 0 |

## 五、验收结论

通用持久化任务计划一期的线上 Workspace 零写入主链路通过。宿主只负责提出受约束计划，中央服务
完成校验、持久化和执行；页面展示的是权威计划进度。最终一轮没有字段猜测、参数重试、直接业务
工具拼接或业务写入。

本记录不证明真实泰华日志已提交。完整“OA 已办 -> 草稿 -> 字段核对 -> 独立授权 -> 泰华提交
-> 权威回读”仍需在具备泰华写权限的身份下另行明确授权验收。
