# 四系统试点收口一期计划

> 建立日期：2026 年 8 月 22 日
>
> 状态：已完成
>
> 目标系统：Seeyon OA、泰华日志系统、语雀部门信息库、照明实验室测试系统

> 验收结果：[四系统试点收口一期结果](./四系统试点收口一期结果-2026-08-22.md)

## 一、目标

本阶段不再以增加工具数量为目标，而是把已有四系统能力收敛为一个可以交付试点的稳定基线：

1. 固定仓库、线上 Release、OpenClaw 插件、MCP 工具目录和用户权限基线；
2. 证明四个系统均能通过同一 AgentBridge、多用户和多端链路稳定使用；
3. 对每个系统分别取得真实成功、真实空结果、登录恢复和明确失败证据；
4. 对 OA 接收处理使用真实待办完成逐流程闭环，不以模拟器代替真实提交；
5. 对照明系统按一期至四期整体人工验收方案完成业务页面核对；
6. 形成统一验收结果、剩余限制和下一阶段进入条件。

## 二、本期边界

本期允许：

- 自动化测试、工具目录检查、服务健康检查和发布一致性检查；
- 四系统会话状态、只读列表、详情、搜索、分析和文件下载；
- 使用 Workspace 自然语言完成只读任务并检查跨端同步；
- 针对精确 OA 真实待办，在用户查看授权卡并批准后执行单条接收处理；
- 对可逆测试动作在独立授权后执行补偿并回读恢复。

本期不允许：

- 为完成验收而制造虚假业务流程、巡检记录或设备告警；
- 未经精确授权执行 OA 审批、照明告警处置或其他业务写入；
- 执行照明开关灯、RTU/回路控制、设备替换、参数配置或删除；
- 使用第二用户的 OA 待办做真实写入；
- 将临时真实失败改写成空结果，或对结果未知的写操作自动重试；
- 在收口期间继续开发第五系统或照明读取五期。

## 五、自动化与线上只读轮

### 5.1 自动化

执行正式全量验证：

```powershell
.\scripts\Invoke-AgentBridgeValidation.ps1 -Mode Full
```

重点记录 Python、OpenClaw、打包清单、compileall 和依赖检查的结果及耗时。测试失败时先判断是
代码缺陷、环境故障还是下游依赖；没有修复和复测前不进入真实业务轮。

### 5.2 发布与健康

执行发布验收脚本的无业务读取检查，核对：

- MCP、管理端、Workspace、systemd 和 Release；
- OpenClaw Gateway 深度 RPC 和插件版本；
- 最近服务错误、活动任务、待投递和身份一致性；
- 两个用户的 OA 会话状态和四个多端 Endpoint。

该轮不读取待办、日志、知识库或照明业务列表，也不执行任何写入。

### 5.3 四系统会话

分别检查四系统会话状态。正确结果可以是：

- `active`：当前已验证有效；
- 明确 `expired`：下游确认失效，后续业务请求应生成登录卡；
- 临时网络或刷新失败：保留会话并返回可重试错误，不能误判为需要密码；
- 租约外：说明不再后台保活，不等同于已退出。

如需登录，完成可信登录后必须自动继续原来的只读请求，不要求用户重复发送。

## 六、Workspace 四系统代表性验收

提示词保持普通用户说法，不包含工具名、内部 ID 或验收编码。

### 6.1 Seeyon OA

依次发送：

> 读取我的 OA 待办。

> 看看最近的已发事项。

> 看看最近的已办事项。

> 看看我的跟踪事项。

> 查看上面第 1 条的详情和流程意见。

通过标准：四个集合独立，列表、详情、意见和上下文一致；没有用已办替代已发或跟踪；任务完成后
状态收口，跨端显示同一结果。

### 6.2 泰华日志

依次发送：

> 看看我上周的工作日志。

> 查看上周正文中出现“项目”的日志。

> 查一个团队成员上周的日志。

> 看看日志系统里的项目。

通过标准：用户、日期、正文关键词和项目条件真正下推；团队查询只返回所选成员；登录恢复后续办
当前请求，不错误续办成个人日志列表。

### 6.3 语雀部门信息库

依次发送：

> 看看部门信息库有哪些知识库。

> 搜索最近和项目有关的内容。

> 打开上面最相关的一篇。

> 把这篇文档的结构和主要内容整理一下。

通过标准：搜索覆盖当前用户有权访问的知识库，文档类型和层级正确，Doc、Sheet、Table 不被当作
同一种正文；登录挑战完成后当前搜索自动续办。

### 6.4 照明实验室

按照
[照明系统整体读取能力人工验收方案](./照明实验室系统/照明系统整体读取能力人工验收方案-2026-08-20.md)
依次完成一期至四期。自动执行可以覆盖 Workspace 和后台证据；页面数字、菜单和字段的最终人工
核对由用户按该文档完成。

## 七、OA 接收处理真实轮

### 7.1 样本选择

只从第一用户当前待办选择样本。优先顺序为：

1. 已经实现但真实证据不足的流程；
2. 可明确判断同意/知会/确认语义的流程；
3. 业务影响低、目标唯一、回读明确的流程；
4. 多条同类型待办可用于验证有序批次的流程。

第二用户只参与读取和隔离验收，不处理其待办。

### 7.2 单条闭环

每条真实待办执行：

```text
读取待办与详情
  -> 识别专用流程能力
  -> 读取表单、意见和附件摘要
  -> 校验节点、模板、表单和当前处理人
  -> 字段卡（确有用户字段时）
  -> 精确授权卡
  -> 单次提交
  -> 待办消失、详情和意见权威回读
  -> 跨端终态与审计检查
```

任何一步出现目标漂移、字段漂移、节点不匹配、业务拒绝或结果未知时停止，不继续处理同批其他事项。

### 7.3 多事项闭环

用户说“处理所有补签申请”时，先冻结候选列表，再逐条产生独立交互。每条拥有独立 `affair_id`、
冻结计划、授权和终态；只完成第一条、卡片被覆盖、重复卡片或剩余事项永久进行中均判为失败。

## 八、双用户和多端收口

至少覆盖：

1. 两个网页用户近同时发起不同系统的只读请求；
2. 第一用户在 Workspace 发起、Telegram 查看或确认；
3. 第二用户在 Workspace 发起、微信接收结果；
4. 任一用户刷新网页后恢复文本、图片、卡片、任务和文件；
5. 同一可信交互在多个合格端显示，但只能完成一次；
6. 任务结束后活动任务、待投递、失败投递和身份一致性违规均回到可解释状态；
7. 任何页面、文件或回复均不出现另一用户的主体、任务或业务内容。

## 九、稳定性观察

业务轮完成后进行持续观察。观察期间不制造写入，只记录：

- 四系统会话状态、最近活动、租约资格和最近保活；
- keepalive 周期中的成功、临时失败、明确过期和连续 deferred；
- OpenClaw Gateway 启动延迟、首次事件延迟、执行超时和通道网络错误；
- Workspace SSE 重连、任务恢复和是否出现孤儿任务；
- 文件卡到期、重新生成和跨用户隔离；
- Linux 服务重启后会话、等待交互和已完成终态是否正确恢复。

观察本身不等于永久登录保证。下游明确注销时，系统应诚实进入过期并在下一次业务请求生成登录卡。

## 十、缺陷分级和停止条件

| 级别 | 示例 | 处理 |
| --- | --- | --- |
| 阻断 | 跨用户数据、未授权写入、重复副作用、结果未知后自动重试 | 立即停止所有相关写能力 |
| 严重 | 登录后续办错误任务、写后无法权威回读、任务永久进行中 | 停止对应系统业务验收，修复后重跑 |
| 一般 | 文案啰嗦、排序不清、页面刷新后延迟显示 | 记录并在收口期修复 |
| 外部 | 下游停机、网络断开、真实样本缺失 | 保存证据，等待条件恢复，不伪造结论 |

## 十一、交付物

本期完成时应产生：

1. 四系统试点收口一期验收结果；
2. 四系统能力、会话、用户和端点的最终矩阵；
3. OA 真实待办逐流程验收记录及未取得样本的清单；
4. 照明一期至四期人工核对记录；
5. 自动化、线上健康、双用户多端和稳定性证据摘要；
6. 已修缺陷、剩余限制、禁止项和下一阶段建议；
7. 更新后的项目当前状态、部署基线和文档导航。

## 十二、完成标准

- 四系统代表性读取均通过真实 Workspace 链路；
- 四系统登录失效、临时失败、租约外和成功恢复的语义正确；
- 第一用户现有 OA 真实待办中，具备专用能力的目标流程完成闭环或明确记录无样本；
- 照明一期至四期按人工方案完成核对，真实空结果和数据质量限制被正确解释；
- 双用户、多端、文件、任务和可信交互没有串用、重复或永久挂起；
- 自动化、发布健康和文档检查全部通过；
- 新项目状态文档明确说明哪些已经真实验收，哪些仍等待业务样本；
- 本期没有为了追求通过率越过业务写入和实体控制安全边界。
