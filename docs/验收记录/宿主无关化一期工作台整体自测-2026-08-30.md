# 宿主无关化一期工作台整体自测 2026-08-30

## 一、结论

宿主无关化一期通过本轮实现后整体自测。OpenClaw 作为当前完整宿主、Reference Host 作为
确定性第二宿主，均继续遵守 `agentbridge.host.v1`；两个真实用户通过各自已经打开的 Agent
Workspace 并发读取 OA 时，身份、任务、Operation、结果和端点保持隔离。本轮发现的兼容登记、
跨轮任务关联、受理后断线恢复和历史空任务问题已经修复、部署并复验。

本轮只执行会话、任务和真实业务读取。没有提交业务写入，没有填写登录凭据，也没有消费仍有效的
授权卡。

## 三、验收方法

本轮不是只看一次查询结果，而是从五层交叉核对：

1. 在两个已经登录的 Workspace 中并发发送不同用户的 OA 只读请求；
2. 在 Task Hub 核对任务终态、任务编号、进行中计数和历史等待任务；
3. 在中央状态库只读核对 Task、Operation、用户主体、事件和 Interaction；
4. 对 Workspace 反向隧道做受理后断线注入，并核对 OpenClaw session 与 AgentBridge 日志；
5. 运行 H01-H25 共享宿主兼容套件和项目全量回归。

### 4.2 任务中心历史状态

辛国茂 Task Hub 原有三条“照明系统概览”长期显示“等待确认”，但这些历史任务没有
`current_interaction_id`、没有 `task_interactions`，其唯一 Operation 已经以
`LOGIN_REQUIRED` 结束，用户实际上没有任何可点击卡片。

修复后刷新 Task Hub：

- 三条不可操作的历史空任务由“等待确认”变为“已过期”；
- 活动任务计数由 3 变为 0；
- 已关联有效 Interaction 的等待任务不受清理影响；
- 李世玉 Task Hub 始终为 0 个活动任务，没有受到另一用户清理影响。

### 4.3 受理后断线恢复

本轮在一个 OA 详情只读任务已经产生工具结果后，主动终止当前 Workspace 反向 SSH 隧道进程。
守护器建立新隧道后，Workspace 从中央账本取回同一 run 的最终文本，任务正常完成。OpenClaw
session 证据为一次 ToolCall、一次 ToolResult、零次 abort，AgentBridge 没有重放业务工具。

修复前，Workspace 只在约 7 秒内查账，隧道虽然恢复但模型最终文本尚未落盘，中央服务会过早
显示 `GATEWAY_CONNECTION_CLOSED`。现在受理后对账窗口为 0、2、5、10、20 秒；只要已经发生
工具活动，就只查账、不重新发送用户请求。

## 五、本轮发现并修复的问题

| 问题 | 根因 | 修复与提交 |
| --- | --- | --- |
| Workspace 重连后偶发不能续办 | 一次性绑定票据已消费，但重连仍沿用旧 grant | 重新签发一次性绑定 grant，`0599fca` |
| 真实登录卡只显示文本或识别失败 | 宿主只识别部分结果外形，未统一读取结构化结果 | 统一识别结构化 Interaction，`2c17041` |
| 自动登录卡没有进入原任务 | 登录 Interaction 创建后缺少可靠的 Task 关联 | 自动把登录卡关联到当前宿主任务，`a1e269a` |
| 新一轮 OA 查询复用旧照明任务 | 新用户轮次错误继承任意 pending Interaction Task | 只允许同一 run 共享任务，新轮次创建新任务，`dc5b672` |
| OpenClaw `0.4.66` 正式调用返回 `FORBIDDEN` | 插件已升级，但中央 L3 兼容登记仍停在 `0.4.65` | 包版本、运行版本和中央兼容版本统一校验，`4fd6684` |
| 受理后短时断线产生假失败 | 对账窗口短于隧道恢复加模型收尾时间 | 延长只读查账窗口且禁止重放，`6b6ffd0` |
| Task Hub 长期保留不可操作的“等待确认” | 旧自动登录路径只留下已结束 Operation，没有关联 Interaction | 15 分钟后把无可操作交互的空任务置为过期，`d4786fd` |

前置的宿主读取续办和连接中断恢复修复在 `dd00b7f`。上述修复都保留失败关闭边界：副作用后的
操作不自动重试，新轮次不继承旧任务，仍有有效 Interaction 或批量任务的等待状态不被清理。

## 八、仍需观察的边界

1. 在部署前的自然故障样本中，反向隧道曾短暂失去服务器 `18789` 监听租约。发生在请求被
   OpenClaw 接受之前时，Workspace 会安全报告“尚未进入业务系统”，不会自动重放。守护器可以
   恢复隧道，但后续仍应继续观察网络切换和远端端口租约的空窗时长。
2. Telegram 与微信偶发外部网络超时属于渠道传输残余风险，不是本轮宿主契约失败；通知 Outbox
   仍按既定退避和下次入站恢复策略工作。
3. 本轮没有人为制造登录失效，也没有为了协议验收创建真实业务写入。L2 登录续办和 L3 真实写
   继续在自然出现合适目标时单独授权验收。

## 九、最终判定

宿主无关化一期满足当前受控试点的完成标准：业务内核不依赖 OpenClaw 私有实现，Reference Host
可以独立验证公开协议，OpenClaw 的 Workspace、Telegram 和微信体验仍由薄适配器承接；任务、
身份、可信交互、文件、恢复和副作用边界以 AgentBridge 中央状态为准。本轮发现的问题已完成代码
修复、正式部署、真实页面复验和全量自动回归。
