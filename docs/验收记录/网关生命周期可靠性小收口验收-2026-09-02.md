# Gateway 生命周期可靠性小收口验收

> 验收日期：2026-09-02
>
> 范围：Windows OpenClaw Gateway、Guard、Workspace 持久投递终态读取和正式发布链路
>
> 安全边界：只检查本机基础设施、中心健康和 Release，不读取业务列表，不执行业务写入。

## 1. 问题与根因

本次收口由一次真实发布重启中的重复恢复触发。生命周期控制器等待 Gateway 启动超过 180 秒时，
旧 Guard 已经拍下“有进程、无监听”的快照；它随后等待同一互斥锁，等控制器启动成功并释放锁后，
仍按旧快照执行第二次重启。问题不是缺少互斥锁，而是互斥锁外的判断结果已经过期。

验收过程中又发现三项相邻问题：

1. 重新安装 Guard 时，计划任务停止后可能遗留旧 PowerShell 子进程；新实例因单实例互斥正常退出，
   安装器却仍可能报告已启动。
2. 生命周期控制器首次看到 `/readyz` 成功后，插件初始化仍可能让端点短暂忙碌；单次 5 秒探针会把
   正常稳定过程误判为发布失败。
3. Workspace 终态和终态事件虽在同一 SQLite 事务提交，流读取端仍可能先读到旧事件页、随后读到
   新终态并立即结束，从而漏掉最后一条消息。

## 2. 实现结果

- 新增 `%LOCALAPPDATA%\AgentBridge\openclaw-lifecycle-operation.json` 共享生命周期租约；记录操作 ID、
  阶段、所有者进程、心跳和到期时间，并使用临时文件原子替换。
- 生命周期控制器在停止、创建前台窗口和等待 `/readyz` 时持续续租。Guard 看到有效租约后只观察，
  不停止进程，也不发起第二次启动。
- 正常结束把租约标为 `completed`；所有者消失或 45 秒没有心跳时租约自动失效，不会永久阻塞自愈。
- Guard 的恢复统一采用 `StartOnly`，取得生命周期互斥锁后重新检查现场；前一个操作已经启动成功时
  返回 `already_running`。
- Guard 安装器会精确停止遗留旧子进程、删除旧状态，并等待新实例写出带租约字段的心跳后才成功。
- 运行时验收增加 45 秒稳定窗口，有界重试 `/readyz` 并等待当前 Gateway 的插件注册证据；不重启服务。
- Workspace 流在看见终态后立即排空同一事务剩余事件；不等待、不重投请求、不唤醒模型。

`lifecycle_in_progress`，Gateway PID 在演练前后均为 `26092`，没有被替换；`/readyz`、前台窗口和
Workspace 隧道均正常，`businessCalls`、`businessListReads`、`businessWrites` 均为 0。

停止，新 Guard 为 `25960`，计划任务状态为 `Running`，并持续写出新格式心跳。
