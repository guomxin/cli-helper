# 协议资源预算与隔离容量补验

日期：2026-09-21。本轮按用户指示只推进资源预算与容量测试；公开材料脱敏取消，两条下游 TLS 配置保持现状。代码基线为本文件所在候选提交，发布仍须经过全量检查、候选 CI 与在线验收；本记录中的隔离结果不代表已上线。

## 实现与边界

- MCP 按认证后从身份库解析的 user_subject 计数，每人最多 8 个活动 HTTP 请求，所有人最多 96 个；同一人的多个令牌共享额度。超额返回 429 与 Retry-After: 1，不排队、不自动重放业务。额度在处理器退出后释放，异常与取消也释放。单用户额度不等于下游业务吞吐承诺。
- H11 协议连接上限 128，同来源 IP 上限 64；超过时关闭新连接。请求头绝对期限 10 秒，请求体绝对期限 60 秒；持续发送少量字节不能续期。keep-alive 后的下一次请求同样受限。写缓冲持续阻塞 30 秒则断开。已开始的业务执行不套用请求体期限，保持既有未知写入结果治理。
- MCP POST 请求体最多 18 MiB，Content-Length 和分块传输均在进入 MCP 业务处理前检查，超限返回 413。认证后的接收请求同样占用用户和全局请求额度。
- 身份验证及额度归属查询的 SQLite 操作通过线程池等待，避免直接阻塞异步事件循环；不缓存认证结果，不改变撤销、有效期或权限规则。
- 固定 Uvicorn 0.51.0，显式使用 H11 协议扩展，禁用此入口未使用的 WebSocket 升级。以后升级 Uvicorn 必须重跑真实套接字测试。
- 配额是当前单进程实例内的配额；多进程或多实例扩容必须重新设计共享预算。NAT 后用户共享 IP 连接上限。未为同一 MCP 端口保留全局耗尽时的健康检查通道。
- TLS 握手发生在 HTTP 协议接管前，仍使用现有 asyncio 握手预算；本轮连接计数不覆盖尚未完成的 TLS 握手，也不是入口级抗分布式资源耗尽方案。两条业务下游 TLS 例外未改动。

## 自动与隔离验证

最终新增 6 项资源测试在 Windows 与 Linux 通过，覆盖：慢请求头与请求体、keep-alive 再次慢发、连接拒绝及恢复；真实 MCP 认证下同人多令牌共享限额与另一用户正常读取；全局额度、异常和取消释放；超大声明长度及分块请求体拒绝且业务未执行；认证数据库等待时事件循环可继续执行。此前 MCP、HTTP 与资源定向回归 55 项通过；最终全量结果以候选发布回执为准。

首轮测试夹具缺少必需的 resource_server_url、旧启动测试使用不具备中间件的 object 占位对象，均已修正。首轮容量脚本对普通文本结果误按结构化结果断言，并发现 Windows SQLite 连接未显式关闭及 RSS 句柄类型错误，均修正后重跑；失败输出不作为通过证据。认证移出事件循环的两轮 Windows 测量受共享机器负载影响，不用于宣称确定的速度提升。

## Linux 隔离容量结果

使用服务器临时目录、回环随机端口、独立进程、临时身份库及只读样本 SQLite，进程 nice=19，单次命令 timeout=180 秒。未读取生产凭据、未访问 OA/照明/日志数据库，未向运行中的服务施压。Python 3.12.3，Uvicorn 0.51.0，主机报告 40 逻辑 CPU；没有独占 CPU 配额。客户端和服务端同进程，峰值 RSS 包含两者且为累计峰值。

16 个合成身份，模拟下游等待固定 50 ms，每个档位运行 5 轮，共 605 次请求，均 HTTP 200 且 count=100、total=4950 正确。

| --- | --- | --- | --- | --- | --- |
| 1 | 5 | 140.54 | 158.82 | 6.85 | 69.21 |
| 8 | 40 | 338.66 | 677.82 | 11.6 | 70.15 |
| 16 | 80 | 636.0 | 1421.06 | 11.28 | 70.78 |
| 32 | 160 | 1091.86 | 2615.4 | 13.31 | 73.9 |
| 64 | 320 | 1800.43 | 3291.03 | 17.87 | 76.4 |

这些数字是入口、认证、协议和小型数据库的隔离基准，不是“同时在线人数”，也不包含真实模型、OA 页面、生产数据库、大文件或 TLS 网络耗时。64 并发时 P95 已超过 3 秒，不能仅因未报错就提高默认额度。暂以 8—16 个同时活动请求作为下一轮真实只读混合负载验收的起点，先观察延迟再扩量；这是一项试验建议，不是生产容量承诺。

可复现实验：`python scripts/measure_mcp_capacity.py --output output/capacity.json`。脚本不接受外部目标，只启动临时回环服务，默认档位 1/8/16/32/64，报告包含运行环境、源文件摘要、延迟、结果正确性和进程峰值内存。只要出现错误返回或错误数据即非零退出。需要减小测试规模可用 `--rounds 1 --levels 1 8`。

本机详细证据：`output/m5-capacity-linux-final.json`、`output/m5-capacity-linux-final.log`、`output/m5-budget-final-tests.log`、`output/m5-budget-regression-final.log`。原始运行输出不提交公开仓库。后续发布使用既定 Publish-AgentBridge.ps1；没有浏览器界面改动，不以浏览器手工操作作为此轮压力测试入口。

## 扩大使用前仍需补验

真实业务混合负载（含模型、OA 和数据库延迟）、长时间稳定性、TLS 握手及网络入口总预算、跨实例配额与健康通道隔离仍需按实际扩容目标实施。本轮完成的是可复现的隔离容量基线和上述具体限制，不宣称所有扩容条件已满足。
