# 通用待办批量处理验收

## 范围

本轮修复“处理所有研发中心效能流程”只完成第一条的问题，扩展为十类已有待办能力的通用批次。
设计见[批量受控任务编排设计](../架构设计/批量受控任务编排设计.md#十五通用待办批量扩展)。
没有操作用户剩余的真实待办，也没有自动批准任何真实业务卡片。

## 已验证

- 五条混合待办顺序推进，不限定两条；中途增加的第六条不进入冻结批次。
- 第二条处理期间重新构造服务，仍从持久账本续办，不重新查询候选、不重复提交。
- 单项成功后、批次推进前模拟中断，恢复只补进度并生成下一张卡。
- 旧回调在下一条已生成授权后到达，返回当前授权，不重新展示旧字段卡。
- 第二条结果未知、拒绝或过期时停止后续项；已成功项不重试。
- 能力版本变化、治理暂停在提交前阻止写入；未消费授权不跨过业务边界。
- 二十三条候选可用显式上限接收；超限、不完整来源、目标消失、重复来源、选择不一致及未支持类型拒绝启动。
- 通用与旧补签批次的重叠目标互斥；第二用户不能读取或恢复第一用户的批次和交互。
- MCP 只读 Token 不能调用通用审批；模型目录不暴露内部批次推进参数。
- OpenClaw 通用批次最终汇总与旧补签兼容；Workspace 展示完成、剩余和停止状态。

## 验证边界

上述连续审批使用隔离测试数据和模拟下游，不代表对真实 OA 的批量审批验收。
Chrome 扩展本轮能发现第一用户 Workspace，但两次读取页面均返回 `Debugger unattached`，未切换 OA 登录会话。
页面代码与多端协调器由自动化回归验证；真实页面点击验收仍有这一工具限制。

## 用户复验

有多条真实待办时发送“处理上面的所有研发中心效能流程”或“处理上面的周报和效能流程”。
核对范围、逐项填写并授权；无需在条目间发送“继续”。最后总数应与冻结列表一致，各端看到同一批次终态。
当前只剩一条符合条件时，应创建一条批次，不能为凑测试数量加入别的待办或重复已办事项。
