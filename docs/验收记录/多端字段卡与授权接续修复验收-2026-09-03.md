# 多端字段卡与授权接续修复验收

## 1. 范围与原因

第一用户从 TG 发起泰华日志填写，Workspace 能看到字段卡；字段提交后没有生成授权卡。
中心记录确认字段已提交但未消费，原任务只有首次准备操作，没有正式业务提交。

8 月 21 日的大列表优化移除了 `details` 中完整结构化结果的副本。OpenClaw 嵌入式运行时
只将 `content`、`details` 传给中间件，导致顶层 MCP 卡片元数据丢失。已有测试直接传原始
结果，没有模拟宿主裁剪。后续 Workspace 专用恢复可以补偿部分路径，但不覆盖 TG 发起任务。

## 2. 修复内容

- 原生代理在宿主裁剪前捕获可信交互，使用已校验身份的协调器呈现、轮询和续办；返回值仍清洗真实入口。
- 普通读取和大列表保持既有返回方式，不复制完整列表到 `details`，不修改 OpenClaw 核心源码。
- 发起端交互通知增加 TG、微信恢复；Workspace 补偿保持拉取式呈现，不改成网页直推。
- 元数据读取失败或卡片投递失败时不确认成功，保留通知重试；微信此类接续失败不依赖下一条用户消息解锁。
- 保留同用户、同任务校验、协调租约和幂等键。重复完成事件不再次续办，终态任务不恢复。
- 续办请求一旦发出但响应丢失，保留执行防重状态并报告错误，不因通知重试重新执行。
- 插件包、注册宿主和运行版本统一为 `0.4.80`，中心兼容清单同步登记该版本的 L3 能力。

## 3. 自动验收

新增回归覆盖：

1. 两个独立身份的原生字段卡，经过实际宿主 `content/details` 裁剪后仍正确呈现；真实入口不进入工具返回正文。
2. TG 和微信发起，字段已完成时从中心通知恢复，产生一张独立授权卡，不调用正式提交工具。
3. 重复完成通知只续办一次、只投递一次；旧 Workspace 完成通知也不再重复读取。
4. 初次投递失败后重试成功，不能提前确认；元数据超时后恢复，微信不等待用户再发消息。
5. 身份冲突、协调租约冲突不能续办。
6. 续办响应丢失后不自动重放。

验证结果：

- 最终固定发布入口的完整回归：798 项通过、3 项跳过、619 个子测试通过。
- 插件全量回归：179 项通过，打包清单检查通过。
- Python 全量曾得到 797 项通过、3 项跳过、618 个子测试通过，另有 1 项测试临时库清理失败。
- 修正测试夹具后，Workspace 与宿主契约的 51 项按文件及失败项复验全部通过，17 个子测试通过。
- Workspace 前端与 Gateway Node 回归：24 项通过；Python 编译和依赖检查通过。
- 运行治理与备份隔离回归：20 项通过，真实业务写入为 0。

测试夹具修正只涉及测试代码：先关闭后台线程再删除临时数据库；允许就绪探测在两秒缓存
过期后再次调用，仍严格校验业务调用次数、身份、幂等参数和返回内容。另一次 localhost HTTP
回归遇到 Windows `WinError 10053`，单独复验通过；没有修改网络或代理，也没有据此修改生产接口。

全量检查曾发现 `0.4.80` 未登记在中心兼容清单中，导致宿主协商降为 L1；已补登记，
并保留根据实际插件包版本验证 L3 的现有回归，避免仅升级插件而无法续办。

此前跳过重复验证的发布尝试被执行器拒绝，未产生远端部署、Gateway 重启或推送副作用。

发布号和健康检查以该次发布入口输出为准。
