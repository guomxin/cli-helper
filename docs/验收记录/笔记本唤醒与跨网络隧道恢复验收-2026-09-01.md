# 笔记本唤醒与跨网络隧道恢复验收 2026-09-01

## 1. 验收目标

针对 Windows 笔记本频繁盒盖待机、从公司带回家、再返回公司并切换有线、无线或 VPN 的
实际使用方式，验证 Agent Workspace 到本机 OpenClaw Gateway 的反向 SSH 隧道能够自行恢复，
且恢复过程不重启正常 Gateway、不进入任何业务系统。

## 2. 本轮变更

- 本机隧道包装器每 2 秒观察网络指纹，并把超过 60 秒的轮询时间跳变识别为系统唤醒；
- 唤醒后主动废弃睡眠前 SSH，会话重建采用最多 2 秒快速退避；
- 隧道在线时每 15 秒刷新状态心跳，记录包装器 PID、SSH PID、最近连接时间和连续失败数；
- SSH 错误不再被下一次尝试覆盖，而是追加保存并归类；
- OpenClaw Guard 增加隧道状态、心跳年龄和进程校验，异常时只重启隧道；
- 安装器改为先停止旧任务和精确包装器，再覆盖任务定义，避免旧进程脱离任务计划程序管理；
- 213 的 `root` 隧道会话启用 `ClientAliveInterval 5`、`ClientAliveCountMax 2`，及时回收
  因盒盖断网而没有正常关闭的旧 `sshd` 和反向端口。

### 3.3 本机恢复演练

1. 运行修正后的安装器，旧包装器 PID `16572` 被新 PID `684` 替换；
2. SSH 子进程由 `9536` 替换为 `11200`，隧道恢复为 `connected`；
3. 受控终止严格匹配的 SSH 子进程后，新 SSH 自动建立；
4. 15 秒状态心跳在同一包装器和 SSH PID 下持续前进；
5. OpenClaw Guard 读取到 `tunnelState=connected`，并记录新鲜的心跳年龄；
6. 整个过程 OpenClaw Gateway PID 始终为 `16676`，没有重启前台 Gateway。
7. `Test-AgentBridgeLocalHostRecovery.ps1 -ExerciseTunnelRestart` 最终返回 `succeeded`，隧道状态
   `connected`、状态年龄 1.4 秒、插件版本 `0.4.71`，所有业务计数均为 0。

PID 只作为本次验收瞬时证据，不作为配置或长期监控条件。

## 5. 结论与剩余人工观察

代码、服务器配置、受控 SSH 中断恢复和真实 `readyz` 链路均通过。至此，笔记本盒盖后旧会话
长期占用远端 `18789` 的主要机制已被本机唤醒识别和服务端主动保活共同覆盖。

真实盒盖无法由自动测试等价模拟。下一次实际从家到公司或从公司到家后，只需观察：

1. `workspace-tunnel-status.json` 是否短暂出现 `resume_detected`；
2. 是否在网络可达后自动回到 `connected`；
3. Workspace 顶部是否自行恢复为“OpenClaw 已连接”；
4. Gateway 前台窗口和 PID 是否保持不变。

若真实观察不符合以上四项，应保留
`%LOCALAPPDATA%\AgentBridge\logs\workspace-tunnel-ssh.log`，其中现在会保存故障分类，不再被
后续重试清空。
