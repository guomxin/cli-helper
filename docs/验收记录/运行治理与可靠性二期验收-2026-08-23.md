6. 发布门禁能否检查就绪状态、备份 timer 和 OpenClaw 版本一致性。

## 3. 核心判据

### 3.1 Trace 与 Span

- Trace 可按用户、宿主、任务、系统、能力和状态查询；
- Operation、可信交互、Task Hub、投递、文件和会话信号可关联到持久化 Trace；
- 终态 Trace 的完成时间不会被随后到达的通知 Span 改写；
- 元数据会脱敏，不保存业务正文、凭据、Cookie 和卡片 URL。

### 3.2 失败分类与副作用

- 写提交结果未知映射到 `B4_COMMIT_ATTEMPTED`，不进入自动重试；
- 权威回读成功映射到 `B5_VERIFIED`，后续只允许恢复通知或文件交付；
- 等待用户和活动中的 Trace 不进入成功率分母；
- 跨用户 Trace、Span 和备份关联异常产生零容忍信号。

### 3.3 事件和恢复

- 相同症状按稳定指纹合并，保留首次、最近和出现次数；
- 事件支持确认、调查、解决和抑制，并保留事件历史；
- 只开放通知重投、投递归档和立即评估三类恢复动作；
- 同一幂等键在首次动作运行中或结束后重复提交都不会再次执行。

### 3.4 备份和就绪

- SQLite 在线备份生成数据库文件和 SHA-256 清单；
- 校验覆盖哈希、`quick_check`、必要表和用户主体关联隔离；
- 篡改备份会被拒绝；
- 管理端和 Workspace 提供独立 `/readyz`，发布验收检查每日备份 timer 和最近结果。

## 5. 结论边界

本期达到受控内网试点的运行治理基线，并进入影子观察期。它不等同于企业生产级可观测平台：

- 当前是单节点 SQLite 和 systemd 每日备份，不是高可用或异机灾备；
- 当前 SLO 用于采集基线和校准阈值，不是对外 SLA；
- 当前恢复动作刻意不重试业务写入；
- 正式告警通知、值班升级、异机恢复演练、WORM 审计和每用户独立 Worker 仍属于后续增强。
