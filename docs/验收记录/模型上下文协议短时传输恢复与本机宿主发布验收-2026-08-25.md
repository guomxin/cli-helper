# 模型上下文协议短时传输恢复与本机宿主发布验收

> 验收日期：2026-08-25
>

>
> OpenClaw：`2026.7.1`
>
> AgentBridge 插件：`0.4.57`

## 1. 验收背景

OA 待办连续处理过程中，中心 AgentBridge 已收到并完成调用，但 OpenClaw 宿主侧偶发
`fetch failed`、`ECONNRESET` 或响应读取中断。原实现把这类短时传输故障直接暴露给模型，
导致用户看到中间报错；Workspace SSE 客户端断开时还可能产生无业务意义的服务器异常日志。

本次收口只处理宿主到 MCP 的传输恢复和 Workspace 断流降噪，不改变 OA 表单、审批语义、
权限边界或最终写入判定。

## 2. 实施内容

- MCP 客户端保留底层传输错误码、重试资格和实际尝试次数；
- 仅对幂等读取和不产生最终业务写入的受治理 `prepare` 调用做 `500 ms`、`2 s` 有界重试；
- `prepare` 在宿主未提供时使用工具调用 ID 生成稳定 `idempotency_key`；
- 所有内部 `commit` 仍然隐藏于模型，且绝不自动重试；
- 重试成功只写宿主诊断日志，不额外向用户发送一次失败消息；
- Workspace 将 `SSLEOFError`、`BrokenPipeError` 和 `ConnectionResetError` 视为客户端正常离开；
- 发布验收将 Gateway RPC、插件加载与外部聊天通道网络探测解耦；
- 发布烟测允许三次只读重试，OpenClaw 控制命令使用 180 秒有界超时，超时时清理整棵诊断进程树。

## 5. 控制面耗时说明

本机 OpenClaw 控制命令冷启动实测约 `70 s`。旧的 90 秒 `--deep` 验收会同时受到外部聊天通道
网络超时影响，并可能在超时后遗留 Node 诊断子进程。当前发布验收只检查本地 Gateway RPC 和
插件加载，外部通道网络质量由独立运行治理信号观察，不再混入 AgentBridge 发布成败。

## 6. 结论

本次验收通过。短时 MCP 传输故障可在明确安全边界内自动恢复，最终业务提交仍保持不重试；
Workspace 客户端断开不再污染服务错误；发布验收不再因聊天通道网络或遗留诊断进程随机失败。
