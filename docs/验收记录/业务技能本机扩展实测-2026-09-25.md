- 单项准备与取消：task `6e478f70-f8a9-4b24-a653-82bd93c7d102`，最终 canceled，旧卡无法填写。
- 批量：task `dfaf9341-e9c4-4eca-96e3-3e16774ec0db`，batch `06c66471-622e-4e18-bf5e-2508d5d1d187`。UTC 01:23:01.641952 task.canceled，01:23:02.718584 batch.item.failed / batch.completed（INTERACTION_SUPERSEDED）将任务变为failed；批量成功数0。对话取消回执和后续任务状态矛盾，不能把初次取消回执当作稳定终态。
- 填单：task `88bc28b9-38f9-4701-9fdf-7787708ade28`。09:29模型表示卡片已准备，但对话卡仍1/5执行中，任务列表等待确认；两次详情入口均返回权限映射错误。取消后页面回执与中央任务最终状态均为 canceled。最终操作清单仅包含读取、转换和 prepare，无审批或日志提交调用。
- Chrome原页中途失去控制连接；重取原页失败后，在同一扩展浏览器新建工作台页，保留 xinguomao 登录恢复测试，未使用 Playwright，也未要求用户重新登录。

以上质量、卡片同步、计划详情权限映射、批量取消终态问题本轮仅记录，尚未修复。不通过扩大用户权限来绕过详情错误。正式审批及日志提交未测试；本轮不构成写入闭环验收。


## 后续修复候选（待上线复测）

- 计划详情仅对属于当前计划、已绑定且在转换注册表中的内部转换继承计划来源权限；所有业务步骤继续检查当前用户权限。修复详情错误及其导致的对话卡无法刷新，不增加业务授权。
- 未提交批量卡的资源失效、父任务取消、批次及剩余项取消在同一 SQLite 事务完成；已提交或已授权的资源仍拒绝取消，后续轮询不能覆盖取消终态。
- 相似案例规则升级为1.0.1：先使用少量状态同义词检索，再按项目和故障对象归并连续记录；不能仅凭项目相同合并，不能以日志条数代替案例数。
- 工作台新增后台 Skill 加载记录卡，展示助手名称、功能、版本、成功或失败原因。参考资料重复加载不重复出卡，历史刷新可恢复，用户之间隔离。卡片明确加载规则不等于业务执行成功；任务卡及详情显示实际绑定，没有绑定时显示未关联 Skill。
- 新增 skill_load_events 表及用户时间索引，发布策略核对线上结构与新增后的精确摘要；旧表和授权不变。
- 复测提示词使用日常表达，不包含 Skill 标识、配置名或任务编号；取消使用上下文中的刚才任务。
