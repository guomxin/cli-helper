# 数据库内容分析固定评测

本评测把查询成功、证据读全、案例相关和结论有据分开。合成来源不含真实用户正文，不要求新增数据库授权，也不调用历史结果接口。

## 固定样本

样本在 `tests/fixtures/analysis_quality.json`，覆盖同名事项、空结果、长文本、分页、相邻无关案例、进展不等于完成、跨时间窗口七类问题。`items` 是人工标注的答案依据，不应放进待评测模型的提示词。`repeat_first` 表示重复首段内容以触发真实证据分页；重复后仍算同一来源段落。

自动测试将样本通过现有 `compile_query → add_evidence → prepare_evidence_page`，并使用错误答案验证四类错误会分别计数。长文本的逐字符续读和分页范围绑定另由 `tests/test_database_evidence.py` 验证。这些检查证明评测框架和证据传输契约，不证明线上模型语义准确率。

## 一次真实模型评测怎么做

1. 固定模型、版本、提示词、日期，记录到答案文件的 `run`。只提供问题、范围和该范围的证据；不得让模型看到标注答案。
2. 按正常分析流程读完分页和长文本片段，保存原始回答。没有读完时必须声明不完整；不得将条数换算为人日、考勤或绩效。
3. 复核人员逐句检查正文、表格和建议，将所有关键结论录成 `items`；来源用原段落定位。没有依据或无法映射的结论也必须记录，不可只摘取正确句子。
4. 运行评测命令并保存原回答、复核表、结果。评分器只比较结构化人工标注，不自动理解自由文本；未逐句复核不得填写 `reviewed_all_claims=true`。

```powershell
python scripts/evaluate_database_analysis.py --cases tests/fixtures/analysis_quality.json --answers output/analysis-answers.json --output output/analysis-quality-result.json
```

答案文件格式（以下仅说明字段，不是模型评测结果）：

```json
{
  "run": {"kind":"model_evaluation", "model":"填写实际版本", "reviewer":"填写复核人"},
  "answers": {
    "progress-not-completion": {
      "query_scope":{"start_date":"2026-09-01","end_date_exclusive":"2026-09-02"},
      "seen_sources":["1"], "complete":true, "unread_fragments":0,
      "reviewed_all_claims":true, "unsupported_metrics":[],
      "items":[{"id":"issue","state":"in_progress","destination":"main","evidence":{"source":"1","paragraph":1}}]
    }
  }
}
```

`state` 取样本支持的 `planned/in_progress/completed`；没有证据不能补成完成。`destination` 区分主表 `main` 与说明排除原因的 `excluded`。缺失样本自动不通过。结果分别列出 `scope/completeness/relevance/support`，不能用一个总通过率掩盖某一类退化。对真实自由文本的细微夸大仍须人工审查。
